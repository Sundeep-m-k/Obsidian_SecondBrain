# Python Internals

## What is it?

Python internals cover how CPython (the standard Python implementation) works under the hood: garbage collection, the GIL (Global Interpreter Lock), memory management, bytecode compilation, and implementation details. Understanding these explains performance mysteries and threading limitations.

---

## Core Concepts

### 1. GIL (Global Interpreter Lock)

The GIL is a mutex that protects CPython internals, allowing only one thread to execute Python bytecode at a time.

**Why the GIL exists:**
CPython's memory management isn't thread-safe. Instead of making all operations thread-safe, there's a single lock (GIL).

**What it means:**
```python
import threading

def cpu_bound():
    # Multiple threads do NOT speed this up
    return sum(range(100_000_000))

threads = []
for _ in range(4):
    t = threading.Thread(target=cpu_bound)
    threads.append(t)
    t.start()

for t in threads:
    t.join()

# 4 threads take roughly 4x longer than 1 thread!
# (Because they share the GIL)
```

**Workarounds:**
```python
# Use multiprocessing (separate processes, separate GILs):
import multiprocessing

def cpu_bound():
    return sum(range(100_000_000))

with multiprocessing.Pool(4) as pool:
    results = pool.map(cpu_bound, range(4))
    # Now 4x faster on 4 cores

# Use async/await (for I/O-bound):
import asyncio

async def fetch():
    # I/O operation (network, disk)
    await asyncio.sleep(1)

async def main():
    await asyncio.gather(fetch(), fetch(), fetch(), fetch())
    # All 4 fetches run concurrently (GIL released during I/O)

# Use C extensions (PyNumpy):
import numpy as np
# Numpy operations release the GIL
```

**When GIL matters:**
```python
# I/O-bound tasks - GIL not a problem:
import threading
import requests

def fetch_url(url):
    requests.get(url)  # GIL released during network I/O

# Can use threading effectively
threads = [threading.Thread(target=fetch_url, args=(url,)) for url in urls]

# CPU-bound tasks - GIL IS a problem:
def compute():
    return sum(range(100_000_000))  # Python holding GIL entire time

# Threading won't help; use multiprocessing
```

### 2. Garbage Collection

Python uses reference counting + cycle detection:

**Reference counting:**
```python
import sys

lst = [1, 2, 3]
print(sys.getrefcount(lst))  # 2 (lst variable + function parameter)

lst2 = lst
print(sys.getrefcount(lst))  # 3 (lst + lst2 + function parameter)

del lst2
print(sys.getrefcount(lst))  # 2

# Object deleted when refcount reaches 0
```

**Circular references (reference cycle):**
```python
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None

a = Node(1)
b = Node(2)
a.next = b
b.next = a  # Circular reference! a→b→a

del a
del b
# Objects not immediately deleted (refcount = 1 for each)
# Cycle detector runs periodically to clean up

# Force garbage collection:
import gc
gc.collect()  # Finds and deletes cycles
```

**How to avoid issues:**
```python
# Break cycles explicitly:
a.next = None
b.next = None

# Or use weak references:
import weakref
a.next = weakref.ref(b)  # Doesn't increment refcount
```

### 3. Memory Management

Python uses memory pools for small objects:

```python
import sys

# Small integers cached:
a = 256
b = 256
print(a is b)  # True (cached)

a = 257
b = 257
print(a is b)  # False (not cached)

# Memory address:
print(id(a))  # Memory address of object

# Size:
x = [1, 2, 3]
print(sys.getsizeof(x))  # ~56 bytes (size of list object, not contents)
```

### 4. Bytecode and Compilation

Python code is compiled to bytecode, then interpreted:

```python
import dis

def example(x):
    y = x + 1
    return y * 2

dis.dis(example)
# Output shows bytecode instructions:
# LOAD_FAST (x from local variables)
# LOAD_CONST (1)
# BINARY_ADD
# LOAD_CONST (2)
# BINARY_MULTIPLY
# RETURN_VALUE

# Check compiled bytecode:
print(example.__code__.co_code)  # Bytecode bytes
print(example.__code__.co_names)  # Names used
```

### 5. How `is` Works

```python
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)    # True (equal content)
print(a is b)    # False (different objects)
print(id(a) == id(b))  # False

# `is` just compares memory addresses:
print(id(a))     # Memory address of a
print(id(b))     # Memory address of b
```

### 6. How Dict Lookup Works

```python
# Dicts use hash tables:
d = {}
d["key"] = "value"

# 1. Hash the key:
hash_value = hash("key")  # ~-1234567890

# 2. Find index in internal array:
index = hash_value % len(d._internal_array)

# 3. Look up value at that index

# O(1) on average, O(n) worst case (hash collision)

# Check hash:
print(hash(5))        # Same hash value every run
print(hash("hello"))  # Same hash value

# Only hashable objects work as keys:
d = {(1, 2): "tuple"}  # ✓ Tuples hashable
d = {[1, 2]: "list"}   # ✗ Lists not hashable
```

### 7. CPython vs Other Implementations

```
CPython - Standard (reference counting + GIL)
Jython - Python in Java VM
IronPython - Python in .NET
PyPy - JIT compiled Python (10x faster but incompatible)
Cython - Python compiled to C
```

### 8. Introspection

```python
class Example:
    def __init__(self, x):
        self.x = x
    
    def method(self):
        pass

obj = Example(5)

# Inspect object:
print(dir(obj))           # All attributes
print(vars(obj))          # Instance __dict__
print(obj.__dict__)       # Same as vars()
print(type(obj))          # <class 'Example'>
print(isinstance(obj, Example))  # True

# Inspect function:
print(example.__name__)   # Function name
print(example.__code__)   # Bytecode object
print(example.__closure__)  # Closure variables

# Dynamic attribute access:
getattr(obj, 'x')         # Get attribute
setattr(obj, 'x', 10)     # Set attribute
hasattr(obj, 'x')         # Check if exists
delattr(obj, 'x')         # Delete attribute
```

## Interview Questions

### Q1: What is the GIL and why does it exist?

The GIL (Global Interpreter Lock) is a mutex in CPython that ensures only one thread executes Python bytecode at a time.

**Why:** CPython's memory management (reference counting) isn't thread-safe. Rather than making everything thread-safe, there's a single lock.

**Impact:**
- I/O-bound code: Not affected (GIL released during I/O)
- CPU-bound code: Multithreading doesn't help (GIL prevents parallelism)

**Solutions:**
- Multiprocessing (separate processes = separate GILs)
- Async/await (for I/O-bound)
- NumPy/C extensions (release GIL)

### Q2: How does Python's garbage collection work?

Python uses:
1. **Reference counting:** Objects deleted when refcount = 0
2. **Cycle detection:** Finds circular references the garbage collector

```python
a = Node()
b = Node()
a.next = b
b.next = a  # Cycle: a→b→a

del a
del b
# Reference counting can't delete (each has refcount=1)
# Cycle detector finds and deletes them
```

### Q3: Why do small integers seem to be the same object?

CPython caches integers -5 to 256 for performance:

```python
print(5 is 5)   # True (cached)
print(257 is 257)  # False (not cached)
```

This is an implementation detail, not guaranteed by Python language spec.

### Q4: Explain how dictionary lookup works

Dicts use hash tables:
1. Hash the key
2. Find index in internal array
3. Look up value

Average case O(1), worst case O(n) (hash collision).

### Q5: When is `is` different from `==`?

- `==` compares value (equality)
- `is` compares memory address (identity)

```python
a = [1, 2, 3]
b = [1, 2, 3]

a == b  # True (same content)
a is b  # False (different objects)
```

### Q6: Why can't lists be dictionary keys?

Lists are mutable. Dictionary keys must be hashable. Hash tables rely on consistent hashing. If a list changes, its hash changes, breaking the dictionary.

### Q7: How would you debug a memory leak in Python?

```python
import tracemalloc

tracemalloc.start()

# Code that might leak

current, peak = tracemalloc.get_traced_memory()
print(f"Current: {current}; Peak: {peak}")

# Use gc module:
import gc
gc.collect()  # Force garbage collection
gc.get_objects()  # List all objects
```

```python
# CPython - reference counting
# PyPy - JIT compilation (10x faster)
# Jython - Java VM (access Java libraries)
# IronPython - .NET VM
```

Most compatible: CPython (standard)
