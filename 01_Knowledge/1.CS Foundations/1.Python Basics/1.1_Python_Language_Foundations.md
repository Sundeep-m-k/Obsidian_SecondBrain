# Python Language Foundations

## What is it?

**Python language foundations** are the bedrock concepts that everything else builds upon: how variables work, how Python stores and accesses data, how scope rules determine what's accessible where, and how Python's object model differs from languages like C++ or Java.

This is not about syntax — it's about **how Python actually thinks**. Understanding these foundations separates engineers who write working code from engineers who write **correct, performant, debuggable code** that doesn't surprise them in production.

> Python is "simple" on the surface but has deep, counterintuitive behaviors hidden underneath. Master the foundations, or you'll spend years debugging mysteries.

---

## Why This Matters (Interview Context)

**In technical interviews:**
- Interviewers ask: "What's the difference between `a = b` and `a = b.copy()`?" and expect you to explain Python's object model
- You'll be asked about scope: "What does this code print?" with a closure or global variable involved
- System design discussions hinge on understanding mutability (why you can't use a list as a dict key)
- Debugging questions assume you understand variable binding and identity

**In production code:**
- Data scientists accidentally mutate shared numpy arrays and corrupt datasets
- Backend developers create thread-safety bugs because they don't understand Python's object model
- ML engineers wonder why changing a model config dict affects other models (shallow vs deep copies)

**In technical interviews for:**
- **Data Analysts:** Understanding variable mutation and scope prevents data pipeline bugs
- **ML Engineers:** Object identity matters when managing models, configs, training state
- **Backend Developers:** Scope and mutability are critical for thread-safe code

## Core Concepts

### 1. Everything is an Object

In Python, **everything** is an object:
- Numbers: `5` is an object
- Strings: `"hello"` is an object
- Functions: `def foo(): pass` creates a function object
- Even types themselves are objects

Every object has three things:
1. **Identity** — a unique ID (`id()`)
2. **Type** — what kind of object it is (`type()`)
3. **Value** — the data it holds

```python
x = 5
print(id(x))        # Identity: 9876543210 (memory address)
print(type(x))      # Type: <class 'int'>
print(x)            # Value: 5
```

**This matters:** Two variables can have the same value but different identities (different objects). Interviewers love asking this.

---

### 2. Variables Are Labels, Not Boxes

**The Critical Misconception:**
Most languages teach variables as "boxes that hold values." Python doesn't work that way.

**The Reality:**
Variables are **labels/references pointing to objects**. Multiple labels can point to the same object.

```python
# Mental model (WRONG - traditional boxes):
# x = [1, 2, 3]  creates a box, puts [1, 2, 3] inside
# y = x          creates another box, copies the value [1, 2, 3]

# Python reality (CORRECT):
x = [1, 2, 3]  # x is a label pointing to a list object at address 0x12345
y = x          # y is another label pointing to THE SAME object at 0x12345

y.append(4)    # We modify THE SHARED object
print(x)       # [1, 2, 3, 4]  -- x changed too!
print(y)       # [1, 2, 3, 4]
print(x is y)  # True - same object!
```

**Memory Diagram:**
```
Before y = x:
x ──┐
    └─> [List object at 0x12345: [1, 2, 3]]

After y = x:
x ──┐
    ├─> [List object at 0x12345: [1, 2, 3]]
y ──┤
```

**Why It Matters:**
- `a = [1, 2]; b = a; b.append(3)` → a is also modified
- Function arguments are passed by reference: `def func(x): x.append(1)` modifies the original list
- Sharing state accidentally in class attributes causes mysterious bugs

---

### 3. Immutable vs Mutable Types

**Immutable types** (cannot change after creation):
- `int`, `float`, `str`, `tuple`, `frozenset`, `bool`, `None`

**Mutable types** (can be modified after creation):
- `list`, `dict`, `set`, `bytearray`, custom classes

```python
# Immutable: str
s = "hello"
s[0] = 'H'  # TypeError! Strings are immutable

# To "change" an immutable, create a new one:
s = "H" + s[1:]  # Creates new string

# Mutable: list
lst = [1, 2, 3]
lst[0] = 99  # ✓ Works! Lists are mutable
```

**Why This Matters:**

1. **Performance:** You can safely share immutable objects; mutable objects need copying
2. **Correctness:** Immutables are thread-safe; mutables need locks
3. **Hashing:** Only immutables can be dict keys or set members

```python
# This works:
d = {(1, 2): "tuple key"}  # tuple is immutable

# This fails:
d = {[1, 2]: "list key"}   # TypeError! lists are mutable
```

### 4. Python's Type System

Python is **dynamically typed** (not statically typed):
- Type is determined at runtime, not declared upfront
- A variable can hold any type
- You can reassign to a different type

```python
x = 5          # x is an int
x = "hello"    # x is now a str (x's type changed!)
x = [1, 2, 3]  # x is now a list
```

**This creates a problem:** How do you know what type a variable should be?

**Answer:** Type hints (Python 3.5+):
```python
def greet(name: str) -> str:
    return f"Hello, {name}"

greet(123)  # Still works! Type hints are not enforced
```

Type hints are **not enforced** by Python (they're used by linters like mypy).

### 5. Scope: LEGB Rule

**Scope** determines which variables are visible from where. Python uses the **LEGB rule**:

1. **Local** — Inside the current function
2. **Enclosing** — In an enclosing function (closures)
3. **Global** — At the module level
4. **Built-in** — Python's built-in names (`len`, `print`, etc.)

```python
x = "global"

def outer():
    x = "enclosing"
    
    def inner():
        x = "local"
        print(x)  # Prints "local"
    
    inner()
    print(x)  # Prints "enclosing"

print(x)  # Prints "global"
```

**The keyword `global`:**
```python
x = 0

def increment():
    global x  # Tell Python: use the global x, not a local one
    x += 1

increment()
print(x)  # 1
```

**The keyword `nonlocal`:**
```python
def outer():
    x = 0
    
    def inner():
        nonlocal x  # Modify the enclosing x, not create a local one
        x += 1
    
    inner()
    print(x)  # 1
```

**Interview Trap:** Without `global`/`nonlocal`, Python assumes you're creating a new local variable:

```python
x = 0

def broken():
    x = x + 1  # UnboundLocalError! x is local, but we're reading it before defining it

def correct():
    global x
    x = x + 1
```

### 6. Identity vs Equality

Two different concepts:

**`is`** checks identity (same object in memory):
```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)      # True (same content)
print(a is b)      # False (different objects)
print(a is c)      # True (same object)
print(id(a) == id(b))  # False
print(id(a) == id(c))  # True
```

**Memory Diagram:**
```
a ──> [List at 0x1000: [1, 2, 3]]
b ──> [List at 0x2000: [1, 2, 3]]
c ──> [List at 0x1000: [1, 2, 3]] (same as a)

a == b → True   (content is equal)
a is b → False  (different objects)
a is c → True   (same object)
```

**When does `is` matter?**
```python
x = None
if x is None:  # ✓ Correct
    pass

if x == None:  # Works, but not idiomatic
    pass

# Small integers are cached:
a = 256
b = 256
print(a is b)  # True! (Python caches -5 to 256)

a = 257
b = 257
print(a is b)  # False! (Different objects)
```

### 7. References and Aliasing

**Aliasing** = multiple names pointing to the same object.

```python
original = [1, 2, 3]
alias = original  # alias points to the same list

# Modifying through one name affects all:
alias.append(4)
print(original)  # [1, 2, 3, 4]
```

**This is intentional and useful**, but dangerous if not understood:

```python
# Common bug in data processing:
data = [[1, 2], [3, 4]]
backup = data  # Thought we made a backup!

data.append([5, 6])
print(backup)  # [1, 2], [3, 4], [5, 6] - backup was modified too!

# Correct way:
backup = data.copy()  # Shallow copy - creates new list object
data.append([5, 6])
print(backup)  # [1, 2], [3, 4] - backup unchanged
```

### 8. Namespaces

A **namespace** is a mapping from names to objects (like a dict).

```python
# Global namespace (module level)
x = 5
y = 10

# Local namespace (inside function)
def func():
    x = 100  # Local x, separate from global x
    print(x)  # 100

print(x)  # 5

# Class namespace
class MyClass:
    x = 200  # Class attribute

obj = MyClass()
print(obj.x)  # 200
obj.x = 300   # Creates instance attribute (shadows class attribute)
print(obj.x)  # 300
print(MyClass.x)  # 200 (class attribute unchanged)
```

**Built-in functions to inspect:**
```python
print(dir())       # Names in current namespace
print(globals())   # Global namespace (dict)
print(locals())    # Local namespace (dict)
```

## Deep Dive: Object Model

### How Assignment Works

```python
x = 5
```

This does NOT copy the value 5. Instead:
1. Python creates an int object with value 5 (or finds existing one)
2. Creates a name `x` in the current namespace
3. Binds `x` to point to that object

```python
x = 5
y = 5

print(x is y)  # True! (small integers cached)
print(id(x) == id(y))  # True

# But with lists:
a = [5]
b = [5]
print(a is b)  # False! (new list objects)
print(id(a) == id(b))  # False
```

### How Function Calls Work

When you call a function, arguments are passed by **reference** (not value, not by name):

```python
def modify_list(lst):
    lst.append(999)  # Modifies the original list

original = [1, 2, 3]
modify_list(original)
print(original)  # [1, 2, 3, 999]

# But reassignment doesn't affect original:
def reassign(lst):
    lst = [999]  # Rebind the local parameter, not the original

original = [1, 2, 3]
reassign(original)
print(original)  # [1, 2, 3]
```

**Memory Diagram (modify_list):**
```
Before call:
original ──> [List at 0x5000: [1, 2, 3]]

During call:
original ──> [List at 0x5000: [1, 2, 3]]
lst ──────┘  (same object)

After lst.append(999):
original ──> [List at 0x5000: [1, 2, 3, 999]]
```

**Memory Diagram (reassign):**
```
Before call:
original ──> [List at 0x5000: [1, 2, 3]]

During call (after lst = [999]):
original ──> [List at 0x5000: [1, 2, 3]]
lst ──────-> [List at 0x6000: [999]]  (different object!)

After call:
original ──> [List at 0x5000: [1, 2, 3]]  (unchanged)
```

## Practical Applications

### For Data Analysts

You frequently work with mutable collections and need to avoid accidental data corruption:

```python
# WRONG - corrupts original data:
import pandas as pd

data = pd.DataFrame({'A': [1, 2, 3]})
backup = data  # Just an alias!
data['A'] = data['A'] * 2
print(backup)  # Also modified!

# CORRECT:
backup = data.copy()  # Actual copy
data['A'] = data['A'] * 2
print(backup)  # Original unchanged
```

### For ML Engineers

Config management and model state require careful object handling:

```python
# WRONG - config is shared across models:
default_config = {'lr': 0.001, 'epochs': 10}

model1_config = default_config
model1_config['lr'] = 0.01  # Accidentally modifies default!

model2_config = default_config
print(model2_config['lr'])  # 0.01 (not intended!)

# CORRECT:
model1_config = default_config.copy()
model2_config = default_config.copy()
```

### For Backend Developers

Thread safety depends on understanding mutability:

```python
# UNSAFE - mutable default:
def add_user(username, users_list=[]):
    users_list.append(username)
    return users_list

print(add_user("alice"))   # ['alice']
print(add_user("bob"))     # ['alice', 'bob'] - unexpected!
print(add_user("charlie")) # ['alice', 'bob', 'charlie']

# SAFE:
def add_user(username, users_list=None):
    if users_list is None:
        users_list = []
    users_list.append(username)
    return users_list
```

## Interview Questions You'll Face

### Q1: What's the difference between `a = b` and `a = b.copy()`?

**Answer:**
`a = b` creates an alias — both `a` and `b` point to the same object in memory. Changes through `a` affect `b` and vice versa.

`a = b.copy()` creates a shallow copy — a new object is created, but if `b` contains mutable objects, those are still shared.

```python
b = [1, [2, 3], 4]
a = b  # Alias
print(a is b)  # True

a = b.copy()  # Shallow copy
print(a is b)  # False (different list objects)
print(a[1] is b[1])  # True (inner list is shared!)

# Modifying the shared inner list:
a[1].append(999)
print(b)  # [1, [2, 3, 999], 4] - b is affected!
```

**Deep copy** copies everything recursively:
```python
import copy
a = copy.deepcopy(b)
print(a[1] is b[1])  # False (inner list also copied)
a[1].append(999)
print(b)  # [1, [2, 3], 4] - b unchanged
```

**Time Complexity:**
- Shallow copy: $O(n)$ where $n$ is number of elements (not recursive)
- Deep copy: $O(n \times d)$ where $d$ is depth (recursive)

### Q2: What does this code print? Explain why.

```python
x = 5
y = 5
print(x is y)

a = 257
b = 257
print(a is b)
```

**Answer:**
First prints `True`, second prints `False`.

**Why:** Python caches small integers (-5 to 256) for performance. The first `5` is the same cached object. But 257 is not cached, so each assignment creates a new int object.

```python
print(id(5))     # Same ID across code
print(id(257))   # Different IDs each time (not cached)
```

This is an implementation detail of CPython (not guaranteed in all Python implementations).

### Q3: Fix this code. What's the bug?

```python
def process_users(users_list=[]):
    users_list.append("new_user")
    return users_list

result1 = process_users()
print(result1)  # ['new_user']

result2 = process_users()
print(result2)  # ['new_user', 'new_user'] - unexpected!
```

**Answer:**
The bug is **mutable default argument**. The default `[]` is created once when the function is defined, not each time the function is called. Every call reuses the same list object.

**Fix:**
```python
def process_users(users_list=None):
    if users_list is None:
        users_list = []
    users_list.append("new_user")
    return users_list
```

### Q4: Explain what happens with this closure:

```python
functions = []
for i in range(3):
    def func():
        return i
    functions.append(func)

print([f() for f in functions])  # What prints?
```

**Answer:**
Prints `[2, 2, 2]`, not `[0, 1, 2]`.

**Why:** Closures capture variables by reference, not by value. By the time any function is called, the loop has finished and `i = 2`. All functions see the same `i`.

**Fix:**
```python
# Capture by value using default argument:
functions = []
for i in range(3):
    def func(i=i):  # i=i captures the current value
        return i
    functions.append(func)

print([f() for f in functions])  # [0, 1, 2]
```

### Q5: What is Python's object model? How does it differ from C++?

**Answer:**
Python's object model is based on **references**. All variables hold references to objects, not the objects themselves.

**Python:**
- Everything is an object with identity, type, and value
- Assignment creates an alias (reference)
- Variables are labels, not boxes
- Type is dynamic (determined at runtime)

**C++:**
- Variables hold values directly (or pointers)
- Assignment copies the value
- Type is static (determined at compile time)
- References are explicit (& operator)

```python
# Python
x = [1, 2, 3]
y = x  # y references the same list
y.append(4)  # x is also modified
```

```cpp
// C++
vector<int> x = {1, 2, 3};
vector<int> y = x;  // y is a COPY
y.push_back(4);     // x is NOT modified
```

### Q6: Name three ways a variable can go out of scope or be deleted:

**Answer:**
1. **Function ends:** Local variables are deleted when function returns
2. **Scope ends:** Variable goes out of block (though Python doesn't have block scope like C)
3. **Explicit deletion:** `del x` removes the name from namespace
4. **Reassignment:** `x = something_else` makes old name point elsewhere
5. **Last reference deleted:** Object is garbage collected when no references remain

```python
def example():
    x = 5  # Created
    # ... x exists here ...
# x deleted here (no more references)

del x  # Explicit deletion
y = y.copy()  # Old y reference deleted (if no other refs)
```

### Q7: When should you use `is` vs `==`?

**Answer:**
- Use `==` for value comparison (do they have the same content?)
- Use `is` for identity comparison (are they the same object?)

**Common cases:**
```python
# Always use 'is':
if x is None:
    pass

if x is True:  # Usually wrong
    pass

# Use '==':
if x == True:  # Better
    pass

if x == 5:
    pass
```

**Why:**
- `None` is a singleton (only one None object exists)
- `True` and `False` are singletons
- Booleans: `1 == True` is True, but `1 is True` might be False
- Using `is` for singletons is faster (pointer comparison vs value comparison)

### Q8: Explain what "everything is an object" means and why it matters:

**Answer:**
In Python, not only data (numbers, strings, lists) are objects — functions, classes, types, and modules are also objects.

**What this means:**
- You can pass functions as arguments
- You can store functions in variables
- You can create functions dynamically
- All objects have identity, type, and value

```python
# Functions are objects:
def greet(name):
    return f"Hello, {name}"

say_hello = greet  # Functions can be assigned
say_hello("Alice")  # "Hello, Alice"

# Classes are objects:
MyClass = type('MyClass', (), {})  # Create class dynamically

# This enables:
# - First-class functions (callbacks, higher-order functions)
# - Functional programming (map, filter, reduce)
# - Decorators (functions that modify functions)
# - Metaprogramming
```

**Why it matters:**
- It enables powerful features (decorators, functional programming)
- It creates mental model consistency (everything works the same way)
- It enables reflection (inspecting objects at runtime)

## Performance and Optimization

### Variable Assignment Performance

```python
# Assignment itself is O(1)
x = y  # Just update a pointer, no copying

# Time: constant
# Space: constant (one more pointer)
```

### Identity Checking vs Equality

```python
# is: Pointer comparison, O(1)
x is y

# ==: Calls __eq__ method, O(n) for most collections
x == y
```

For large lists, `is` is much faster but checks different thing:
```python
big_list = list(range(1_000_000))
another_list = list(range(1_000_000))

%timeit big_list is another_list      # 0.01 µs (instant)
%timeit big_list == another_list      # 100 µs (much slower)
```

### Scope Lookup Performance

```python
# Fast: local variable
def fast():
    x = 5
    return x

# Slower: global variable (requires namespace lookup)
y = 5
def slower():
    global y
    return y
```

Local variables are stored in an array (fast), globals in a dict (slower).
