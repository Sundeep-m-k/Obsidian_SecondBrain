# Python Object-Oriented Programming

## What is it?

Object-oriented programming (OOP) organizes code around objects that combine data (attributes) and behavior (methods). Python's OOP implementation supports inheritance, polymorphism, and encapsulation. Understanding Python's object model (classes, inheritance, MRO, dunder methods) is critical for writing professional code and passing interviews.

---

## Core Concepts

### 1. Classes and Objects

```python
class Dog:
    # Class attribute (shared by all instances):
    species = "Canis familiaris"
    
    # Constructor (instance initialization):
    def __init__(self, name, age):
        self.name = name      # Instance attribute
        self.age = age
    
    # Instance method:
    def bark(self):
        return f"{self.name} says Woof!"
    
    # String representation:
    def __str__(self):
        return f"Dog({self.name}, {self.age})"

# Create objects:
dog1 = Dog("Rex", 3)
dog2 = Dog("Buddy", 5)

print(dog1.name)       # "Rex"
print(dog1.bark())     # "Rex says Woof!"
print(dog1.species)    # "Canis familiaris"
print(dog1)            # Dog(Rex, 3)
```

**Class vs Instance Attributes:**
```python
class Counter:
    count = 0  # Class attribute (shared)
    
    def __init__(self):
        self.value = 0  # Instance attribute

c1 = Counter()
c2 = Counter()

c1.value = 10
print(c1.value, c2.value)  # 10, 0 (separate)

Counter.count += 1
print(c1.count, c2.count, Counter.count)  # 1, 1, 1 (shared)

c1.count = 999  # Creates instance attribute, shadows class attribute
print(c1.count, c2.count, Counter.count)  # 999, 1, 1
```

### 2. Inheritance

```python
# Base class (parent):
class Animal:
    def __init__(self, name):
        self.name = name
    
    def speak(self):
        return f"{self.name} makes a sound"

# Derived class (child):
class Dog(Animal):
    def speak(self):  # Override parent method
        return f"{self.name} barks"

# Usage:
dog = Dog("Rex")
print(dog.speak())  # "Rex barks" (uses Dog's speak)

# Call parent method:
class Dog(Animal):
    def speak(self):
        parent_speak = super().speak()  # Call Animal.speak()
        return parent_speak.replace("sound", "bark!")

print(dog.speak())  # "Rex makes a sound bark!"
```

### 3. Method Types

```python
class Example:
    class_var = "class"
    
    # Instance method (has access to self):
    def instance_method(self):
        print(f"Instance: {self.class_var}")
    
    # Class method (has access to class):
    @classmethod
    def class_method(cls):
        print(f"Class: {cls.class_var}")
    
    # Static method (no access to self or cls):
    @staticmethod
    def static_method():
        print("Static: No access to instance or class")

obj = Example()
obj.instance_method()        # Instance: class
Example.class_method()        # Class: class
Example.static_method()       # Static: No access...

# When to use:
# - instance_method: Operate on instance data
# - @classmethod: Factory methods, alternative constructors
# - @staticmethod: Utility functions related to class

class Date:
    def __init__(self, day, month, year):
        self.day = day
        self.month = month
        self.year = year
    
    @classmethod
    def from_string(cls, date_string):  # Factory method
        day, month, year = date_string.split("-")
        return cls(int(day), int(month), int(year))

d = Date.from_string("15-3-2024")  # Alternative constructor
```

### 4. Dunder Methods (Magic Methods)

Methods with double underscores that Python calls automatically:

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    
    # String representation (user-friendly):
    def __str__(self):
        return f"Person({self.name}, {self.age})"
    
    # Official representation (debugging):
    def __repr__(self):
        return f"Person('{self.name}', {self.age})"
    
    # Comparison:
    def __eq__(self, other):
        return self.name == other.name and self.age == other.age
    
    def __lt__(self, other):
        return self.age < other.age
    
    # Arithmetic:
    def __add__(self, years):
        return Person(self.name, self.age + years)
    
    # Container:
    def __len__(self):
        return len(self.name)
    
    def __getitem__(self, index):
        return self.name[index]
    
    # Callable:
    def __call__(self, times):
        return f"{self.name} " * times

p1 = Person("Alice", 30)
p2 = Person("Bob", 25)

print(str(p1))      # Person(Alice, 30)
print(repr(p1))     # Person('Alice', 30)
print(p1 == p2)     # False
print(p1 > p2)      # True
print(p1 + 5)       # Person(Alice, 35)
print(len(p1))      # 5
print(p1[0])        # 'A'
print(p1(3))        # Alice Alice Alice
```

### 5. Encapsulation & Properties

```python
class BankAccount:
    def __init__(self, balance):
        self._balance = balance  # Protected (convention: _)
    
    # Getter:
    @property
    def balance(self):
        return self._balance
    
    # Setter:
    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("Balance cannot be negative")
        self._balance = value
    
    # Deleter:
    @balance.deleter
    def balance(self):
        print("Deleting balance")
        del self._balance

account = BankAccount(1000)
print(account.balance)     # 1000
account.balance = 2000     # Uses setter
account.balance = -500     # ValueError!
del account.balance        # Uses deleter
```

### 6. Method Resolution Order (MRO)

Python uses C3 Linearization to determine method resolution in multiple inheritance:

```python
class A:
    def method(self):
        return "A"

class B(A):
    def method(self):
        return "B"

class C(A):
    def method(self):
        return "C"

class D(B, C):
    pass

print(D.mro())  # [D, B, C, A, object]

d = D()
print(d.method())  # "B" (B comes before C in MRO)

# Check MRO:
print(D.__mro__)  # Class tuple
d.__class__.__mro__  # From instance
```

**MRO Rules:**
1. Children checked before parents
2. Left-to-right order in inheritance list
3. Each class appears only once

## Practical Examples

### 1. Abstract Base Classes

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    @abstractmethod
    def speak(self):
        pass
    
    @abstractmethod
    def move(self):
        pass

class Dog(Animal):
    def speak(self):
        return "Woof!"
    
    def move(self):
        return "Running"

dog = Dog()  # ✓ Works

animal = Animal()  # TypeError! Cannot instantiate abstract class
```

### 2. Mixins (Multiple Inheritance)

```python
class Flyable:
    def fly(self):
        return "Flying"

class Swimmable:
    def swim(self):
        return "Swimming"

class Duck(Flyable, Swimmable):
    pass

duck = Duck()
print(duck.fly())   # Flying
print(duck.swim())  # Swimming
```

### 3. Dataclasses (Python 3.7+)

```python
from dataclasses import dataclass

@dataclass
class Person:
    name: str
    age: int
    
    def greet(self):
        return f"Hello, I'm {self.name}"

p = Person("Alice", 30)
print(p)  # Person(name='Alice', age=30)
print(p.greet())  # Hello, I'm Alice

# Equivalent to:
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    
    def __repr__(self):
        return f"Person(name={self.name!r}, age={self.age!r})"
```

## Interview Questions

### Q1: Explain the difference between `__str__` and `__repr__`

`__str__` is for end users (human-readable); `__repr__` is for developers (unambiguous).

```python
class Person:
    def __str__(self):
        return f"Person {self.name}"  # "Person Alice"
    
    def __repr__(self):
        return f"Person('{self.name}')"  # Person('Alice')
```

### Q2: What's the difference between class attributes and instance attributes?

Class attributes are shared by all instances; instance attributes are separate per instance.

```python
class Dog:
    species = "Canis"  # Class attribute
    
    def __init__(self, name):
        self.name = name  # Instance attribute

d1 = Dog("Rex")
d2 = Dog("Buddy")

d1.name = "Duke"
print(d1.name, d2.name)  # "Duke", "Buddy" (separate)

Dog.species = "Wolf"
print(d1.species, d2.species)  # "Wolf", "Wolf" (shared)
```

### Q3: Explain inheritance and super()

Inheritance allows classes to inherit behavior from parent classes. `super()` calls parent methods.

```python
class Animal:
    def speak(self):
        print("Some sound")

class Dog(Animal):
    def speak(self):
        super().speak()  # Call parent
        print("Woof!")
```

### Q4: What's the MRO and how does Python determine it?

Method Resolution Order (MRO) is the order Python searches for methods in inheritance hierarchy. Python uses C3 Linearization algorithm.

```python
print(ClassName.mro())
print(ClassName.__mro__)
```

### Q5: Explain properties and when to use them

Properties allow you to use getter/setter logic while maintaining attribute-like syntax.

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius
    
    @property
    def radius(self):
        return self._radius
    
    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError("Radius must be positive")
        self._radius = value

c = Circle(5)
c.radius = -10  # ValueError! (setter validates)
```

### Q6: Difference between @classmethod and @staticmethod?

- `@classmethod`: Has access to class via `cls`
- `@staticmethod`: No access to instance or class

```python
class Factory:
    @classmethod
    def create(cls):  # Can access cls
        return cls()
    
    @staticmethod
    def utility():  # No access to self or cls
        return "utility"
```

### Q7: How would you make a class immutable?

Use `__slots__` and avoid setters:

```python
class ImmutablePerson:
    __slots__ = ['name', 'age']
    
    def __init__(self, name, age):
        object.__setattr__(self, 'name', name)
        object.__setattr__(self, 'age', age)
    
    def __setattr__(self, name, value):
        raise AttributeError("Object is immutable")

p = ImmutablePerson("Alice", 30)
p.name = "Bob"  # AttributeError!
```

### Q8: Explain polymorphism in Python

Polymorphism allows objects of different types to respond to the same interface.

```python
class Dog:
    def speak(self):
        return "Woof"

class Cat:
    def speak(self):
        return "Meow"

def animal_sound(animal):
    print(animal.speak())

dog = Dog()
cat = Cat()

animal_sound(dog)  # Woof
animal_sound(cat)  # Meow
```
