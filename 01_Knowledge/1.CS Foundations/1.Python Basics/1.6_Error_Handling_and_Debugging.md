# Python Error Handling and Debugging

## What is it?

Error handling manages exceptions (runtime errors); debugging finds and fixes problems. Python's exception system lets you catch and handle errors gracefully. Understanding exception hierarchy, context managers, and debugging techniques is critical for writing robust production code.

---

## Core Concepts

### 1. Exception Hierarchy

```python
# Python's exception hierarchy:
BaseException
├── SystemExit
├── KeyboardInterrupt
├── GeneratorExit
└── Exception
    ├── StopIteration
    ├── ArithmeticError
    │   ├── FloatingPointError
    │   ├── OverflowError
    │   └── ZeroDivisionError
    ├── AssertionError
    ├── AttributeError
    ├── ImportError
    ├── LookupError
    │   ├── IndexError
    │   └── KeyError
    ├── NameError
    ├── RuntimeError
    ├── SyntaxError
    ├── TypeError
    ├── ValueError
    └── ... (many more)
```

**Never catch BaseException:**
```python
# WRONG - catches SystemExit and KeyboardInterrupt:
try:
    func()
except BaseException:
    pass

# CORRECT - catches normal exceptions:
try:
    func()
except Exception:
    pass
```

### 2. try-except-else-finally

```python
try:
    # Code that might raise exception
    result = 10 / int(user_input)
except ValueError:
    # Handle ValueError specifically
    print("Invalid integer input")
except ZeroDivisionError:
    # Handle ZeroDivisionError
    print("Cannot divide by zero")
except Exception as e:
    # Catch all other exceptions
    print(f"Unexpected error: {e}")
else:
    # Executes if no exception occurred
    print(f"Result: {result}")
finally:
    # Always executes (cleanup)
    print("Done")
```

**Flow:**
```
1. Try block executes
2. If exception → matching except block executes
3. If no exception → else block executes
4. Finally always executes (whether exception or not)
5. After except or else → finally → continue
```

### 3. Raising Exceptions

```python
# Raise built-in exception:
def validate_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    if age > 150:
        raise ValueError("Age seems unrealistic")
    return age

# Custom exception:
class CustomError(Exception):
    pass

def func():
    raise CustomError("Something went wrong")

# Re-raise current exception:
try:
    func()
except CustomError as e:
    print(f"Caught: {e}")
    raise  # Re-raise the same exception

# Chain exceptions:
try:
    func()
except CustomError as e:
    raise RuntimeError("Failed to process") from e
```

### 4. Custom Exceptions

```python
class InvalidConfigError(Exception):
    """Raised when configuration is invalid"""
    pass

class NetworkError(Exception):
    """Raised when network operation fails"""
    def __init__(self, message, code):
        self.message = message
        self.code = code
        super().__init__(f"{message} (code: {code})")

# Use:
try:
    if not config.is_valid():
        raise InvalidConfigError("Missing required fields")
except InvalidConfigError as e:
    print(f"Config error: {e}")
```

### 5. Context Managers (with statement)

Automatically setup and cleanup:

```python
# Without context manager:
f = open('file.txt')
try:
    data = f.read()
finally:
    f.close()  # Always runs

# With context manager:
with open('file.txt') as f:
    data = f.read()  # File auto-closed even if error

# Multiple resources:
with open('input.txt') as f_in, open('output.txt', 'w') as f_out:
    for line in f_in:
        f_out.write(line)  # Both files auto-closed

# Create custom context manager:
class Database:
    def __enter__(self):
        print("Opening database")
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        print("Closing database")
        # exc_type, exc_val, exc_tb describe any exception
        return False  # Don't suppress exceptions

with Database() as db:
    # Use db
    pass  # Database closes automatically

# Using decorator:
from contextlib import contextmanager

@contextmanager
def open_database():
    print("Opening")
    db = Database()
    try:
        yield db
    finally:
        print("Closing")
        db.close()

with open_database() as db:
    pass
```

### 6. Debugging Techniques

```python
# Print debugging:
x = 5
print(f"x = {x}")  # Simple
print(f"DEBUG: x = {x}, type = {type(x)}")

# Assertions:
def calculate(x):
    assert x > 0, "x must be positive"
    return x ** 2

calculate(-5)  # AssertionError

# pdb (Python Debugger):
import pdb
pdb.set_trace()  # Breakpoint

# Python 3.7+:
breakpoint()  # Equivalent to pdb.set_trace()

# Post-mortem debugging:
try:
    func()
except Exception:
    import pdb
    pdb.post_mortem()  # Debug the exception that just happened

# Logging (for production):
import logging
logging.basicConfig(level=logging.DEBUG)
logger = logging.getLogger(__name__)

logger.debug("Debug info")
logger.info("General info")
logger.warning("Warning")
logger.error("Error")
logger.critical("Critical")
```

### 7. Assertions

```python
# Enable assertions in normal code:
assert condition, "Error message"

# Example:
def divide(a, b):
    assert b != 0, "Divisor cannot be zero"
    return a / b

# Disable assertions with -O flag:
# python -O script.py  # Assertions are ignored

# Use for internal checks, not user input:
def process(data):
    assert isinstance(data, dict), "data must be dict"
    # User should never pass wrong type to this
    # But internal invariants should be asserted
```

## Advanced Concepts

### 1. Exception Chaining

```python
try:
    try:
        file = open('missing.txt')
    except FileNotFoundError as e:
        raise RuntimeError("Config file not found") from e
except RuntimeError as e:
    print(f"Error: {e}")
    print(f"Caused by: {e.__cause__}")
    print(f"Traceback: {e.__traceback__}")
```

### 2. Graceful Degradation

```python
def fetch_user(user_id):
    try:
        response = requests.get(f"https://api.example.com/users/{user_id}")
        response.raise_for_status()
        return response.json()
    except requests.ConnectionError:
        logger.warning("Network error, using cached data")
        return get_cached_user(user_id)
    except requests.HTTPError as e:
        logger.error(f"HTTP error: {e}")
        return None
```

### 3. Exception Handling in Comprehensions

```python
# Dictionary comprehension with exception handling:
def safe_int(s):
    try:
        return int(s)
    except ValueError:
        return None

numbers = {s: safe_int(s) for s in ['1', '2', 'three', '4']}
# {'1': 1, '2': 2, 'three': None, '4': 4}

# Generator with exception handling:
def process_items(items):
    for item in items:
        try:
            yield process(item)
        except ValueError:
            logger.warning(f"Skipping invalid item: {item}")
            continue
```

## Interview Questions

### Q1: Explain try-except-else-finally

```python
try:
    result = 10 / int(input("Number: "))
except ValueError:
    print("Invalid input")
except ZeroDivisionError:
    print("Can't divide by zero")
else:
    print(f"Result: {result}")  # Runs only if no exception
finally:
    print("Done")  # Always runs
```

### Q2: When would you use custom exceptions?

Custom exceptions make code clearer and enable specific handling:

```python
class InsufficientFundsError(Exception):
    pass

class BankAccount:
    def withdraw(self, amount):
        if amount > self.balance:
            raise InsufficientFundsError(f"Need ${amount}, have ${self.balance}")
        self.balance -= amount

try:
    account.withdraw(1000)
except InsufficientFundsError as e:
    print(f"Cannot process: {e}")
```

### Q3: What's the difference between `except Exception` and `except BaseException`?

`BaseException` includes `KeyboardInterrupt` and `SystemExit` (you usually don't want to catch these).

```python
# WRONG:
except BaseException:
    pass  # Catches Ctrl+C, preventing exit

# RIGHT:
except Exception:
    pass  # Only catches normal errors
```

### Q4: Explain context managers and when to use them

Context managers (with statement) ensure cleanup:

```python
# File is closed automatically:
with open('file.txt') as f:
    data = f.read()

# Lock is released automatically:
with thread_lock:
    critical_section()

# Database connection is closed:
with database.connection() as conn:
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM users")
```

### Q5: How would you debug this code?

```python
def calculate(data):
    result = 0
    for item in data:
        result += item / len(data)  # Bug: dividing by len, not per-item
    return result
```

**Options:**
1. Print debugging
2. Use pdb: `import pdb; pdb.set_trace()`
3. Use assertions: `assert len(data) > 0`
4. Add logging

### Q6: What's the difference between `raise` and `raise ... from`?

```python
# Re-raise current exception:
try:
    func()
except CustomError:
    raise  # Re-raises CustomError with original traceback

# Chain exceptions (shows cause):
try:
    func()
except CustomError as e:
    raise RuntimeError("High-level error") from e
    # Shows both: RuntimeError caused by CustomError
```

### Q7: How would you handle exceptions in a loop without stopping?

```python
# Option 1: Catch in loop
for item in items:
    try:
        process(item)
    except ValueError:
        logger.warning(f"Skipping invalid: {item}")
        continue

# Option 2: Generator with error handling
def safe_process(items):
    for item in items:
        try:
            yield process(item)
        except ValueError:
            logger.warning(f"Skipping: {item}")
            yield None

for result in safe_process(items):
    if result is not None:
        handle(result)
```

### Q8: What are assertions used for?

Assertions check internal invariants (things that should never be false):

```python
def binary_search(arr, target):
    assert isinstance(arr, list), "arr must be list"
    assert all(arr[i] <= arr[i+1] for i in range(len(arr)-1)), "arr must be sorted"
    # ... search logic

# Not for user input:
age = int(input("Age: "))
if age < 0:  # ← Handle with if/except
    raise ValueError("Age must be positive")

# For internal guarantees:
result = calculate(x)
assert result > 0  # ← Check invariant with assert
```

## Performance Notes

```python
# Exception raising is slow:
%timeit x = 1/0  # ~5 µs (exception created)

# Normal control flow is faster:
%timeit if x == 0: pass  # ~0.01 µs

# Don't use exceptions for control flow:
# WRONG:
try:
    while True:
        x = iter.next()  # Raises StopIteration
except StopIteration:
    break

# RIGHT:
for x in iter:
    pass

# Context managers have minimal overhead:
%timeit with lock: pass  # ~0.1 µs
```
