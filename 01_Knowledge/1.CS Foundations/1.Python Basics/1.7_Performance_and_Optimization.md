# Python Performance and Optimization

## What is it?

Python is slower than C++ or Java, but understanding performance bottlenecks, profiling, and optimization techniques can make programs 10-100x faster. This section covers Big-O analysis for Python structures, profiling, optimization strategies, and when premature optimization is genuinely evil.

---

## Big-O Complexity in Python

### Data Structure Operations

| Operation | List | Dict | Set | Tuple |
|-----------|------|------|-----|-------|
| Access | O(1) | O(1) | — | O(1) |
| Search | O(n) | O(1) | O(1) | O(n) |
| Insert | O(n) | O(1) | O(1) | — |
| Delete | O(n) | O(1) | O(1) | — |
| Append | O(1)* | — | — | — |
| Sort | O(n log n) | — | — | — |

*Amortized O(1)

### Common Algorithms

```python
# O(1) - Constant
x = arr[0]
d = {key: value}

# O(log n) - Logarithmic
import bisect
bisect.bisect_left(sorted_arr, target)

# O(n) - Linear
for item in arr:
    process(item)

# O(n log n) - Linearithmic
sorted_arr = sorted(arr)

# O(n²) - Quadratic
for i in arr:
    for j in arr:
        compare(i, j)

# O(2ⁿ) - Exponential
# Fibonacci, subsets, permutations

# O(n!) - Factorial
# All permutations
```

## Profiling

### Using timeit

```python
import timeit

# Quick measurement:
setup = "x = list(range(1000))"
time1 = timeit.timeit("x.append(1000)", setup=setup, number=1000000)
time2 = timeit.timeit("x.insert(0, 0)", setup=setup, number=1000000)

print(f"append: {time1:.4f}s")
print(f"insert: {time2:.4f}s")
# append: 0.0500s
# insert: 2.5000s
```

### Using cProfile

```python
import cProfile

def slow_function():
    result = 0
    for i in range(1000):
        result += sum(range(i))
    return result

cProfile.run('slow_function()')
# Output:
# ncalls  tottime  cumtime  filename:lineno(function)
#    1000    0.001    0.002  {built-in method sum}
```


## Optimization Techniques

### 1. Choose Right Data Structure

```python
# SLOW - O(n) search in list:
visited = []
for item in stream:
    if item in visited:  # O(n) each time!
        process_duplicate(item)
    visited.append(item)

# FAST - O(1) search in set:
visited = set()
for item in stream:
    if item in visited:  # O(1)
        process_duplicate(item)
    visited.add(item)

# Benchmark:
import timeit

# 1000 items:
list_time = timeit.timeit(
    "x in [range(1000)]",
    setup="x = 999",
    number=10000
)  # ~0.5s

set_time = timeit.timeit(
    "x in {range(1000)}",
    setup="x = 999",
    number=10000
)  # ~0.001s
```

### 2. Use Appropriate Algorithms

```python
# SLOW - Linear search O(n):
target = 42
index = None
for i, val in enumerate(sorted_arr):
    if val == target:
        index = i
        break

# FAST - Binary search O(log n):
import bisect
index = bisect.bisect_left(sorted_arr, target)

# Benchmark with 1M elements:
# Linear: ~0.5M comparisons
# Binary: ~20 comparisons
```

### 3. Cache Expensive Computations

```python
# SLOW - Recompute each call:
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

%timeit fibonacci(30)  # ~0.5s (repeated work)

# FAST - Memoize results:
from functools import lru_cache

@lru_cache(maxsize=None)
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

%timeit fibonacci(30)  # ~0.0001s (cached)
```

### 4. Vectorization (Numpy)

```python
import numpy as np

# SLOW - Python loop:
result = []
for i in range(1000000):
    result.append(data[i] * 2 + 1)

# FAST - Vectorized:
result = data * 2 + 1

# Benchmark:
# Loop: ~100ms
# Numpy: ~5ms
```

### 5. String Concatenation

```python
# SLOW - O(n²):
result = ""
for word in words:
    result = result + word

# FAST - O(n):
result = "".join(words)

# Benchmark with 1000 words:
# Concatenation: ~100ms
# join: ~0.1ms
```

### 6. List Comprehension vs Loop

```python
# Loop (slower):
squares = []
for x in range(1000):
    squares.append(x**2)

# Comprehension (faster):
squares = [x**2 for x in range(1000)]

# Benchmark:
# Loop: ~10µs
# Comprehension: ~8µs (10-15% faster)
```

### 7. Generator for Large Data

```python
# List - stores all in memory:
data = [x**2 for x in range(1_000_000)]  # ~40MB

# Generator - minimal memory:
data = (x**2 for x in range(1_000_000))  # ~1KB

# Use when iterating once:
for item in data:
    process(item)
```

### 8. Avoid Redundant Work

```python
# SLOW - Recompute in loop:
for item in items:
    if len(items) > 0:  # ← Recomputed each iteration!
        process(item)

# FAST - Compute once:
n = len(items)
for item in items:
    if n > 0:  # ← Computed once
        process(item)

# Python optimizes some cases:
for i in range(len(items)):  # ← len() called each time... sometimes
    pass
```

## Interview Questions

### Q1: Explain Big-O complexity for list operations

```python
lst = [1, 2, 3, 4, 5]

lst[0]          # O(1) - direct index access
lst.append(6)   # O(1) amortized - occasional reallocation
lst.insert(0, 0) # O(n) - must shift all elements
2 in lst        # O(n) - must scan entire list
```

### Q2: When would you use a set instead of a list?

Use sets when:
- Membership testing is frequent (O(1) vs O(n))
- Uniqueness matters
- Order doesn't matter

```python
# Slow - O(n) check:
if item in item_list:
    pass

# Fast - O(1) check:
if item in item_set:
    pass
```

### Q3: How would you optimize this code?

```python
# SLOW:
result = []
for i in range(1000):
    for j in range(1000):
        if i * j < 1000:
            result.append(i * j)

# FAST:
result = [i * j for i in range(1000) for j in range(1000) if i * j < 1000]
```

### Q4: Explain caching and when to use it

Caching stores results to avoid recomputation:

```python
from functools import lru_cache

@lru_cache(maxsize=128)
def expensive_function(n):
    # Computed once per unique n
    return sum(range(n))

# Call 1000 times with 100 unique values:
# First 100 calls compute; next 900 use cache
```

### Q5: Compare list vs generator memory usage

```python
# List: All in memory at once
data = [x**2 for x in range(1_000_000)]  # ~40MB

# Generator: One at a time
data = (x**2 for x in range(1_000_000))  # ~1KB
```

Use generators for large datasets or single-pass processing.

### Q6: What's the performance penalty of using exceptions?

```python
# Normal flow - fast:
if key in dict:
    value = dict[key]

# Exception-based - slow:
try:
    value = dict[key]
except KeyError:
    pass

# Exceptions are ~5-10x slower than normal flow
# Don't use for control flow
```

## Optimization Strategy

1. **Measure first** - Use profiler to find real bottleneck
2. **Choose right algorithm** - O(n log n) vs O(n²) often matters most
3. **Choose right data structure** - List vs set can be 100x difference
4. **Optimize micro-operations** - After choosing right algo/structure
5. **Consider trade-offs** - Speed vs readability vs memory

**Premature optimization is the root of all evil:**
```python
# Don't micro-optimize without proof:
x = [1, 2, 3]
y = x[:]  # Slightly faster than x.copy(), but less clear

# Instead, write clear code first, then profile
```

## One-line Summary

> Python optimization requires profiling to find bottlenecks, choosing right data structures and algorithms (which matter most), then micro-optimizing if needed.
