# Feature Scaling and Normalization

## What is it?

**Feature scaling** transforms numerical features to comparable ranges. Raw features may have vastly different scales:
- Age: 0-100
- Income: $0-$10,000,000
- Height: 50-250 cm

**Scaling makes:** All features contribute equally to model training; gradient descent converges faster; distance-based models (KNN, SVM) become fair.

---

## Why Scaling Matters

### Problem 1: Gradient Descent Convergence

Without scaling:
```
Features: Age (0-100), Income (0-10M)

Cost surface is elongated (elliptical):
  Loss
   ^
   |   .-''─''-.
   | .'          '.     ← Income (10M scale)
   |'              '
   └─────────────────> Age (100 scale)

Gradient descent: Step size OK for income, tiny for age.
Result: Slow convergence, zigzagging path, may not converge.
```

With scaling (both 0-1):
```
  Loss
   ^
   |        .─.
   |      .'   '.    ← Both scaled
   |     '       '
   └─────────────> Features
   
Gradient descent: Smooth, efficient descent. Fast convergence.
```

### Problem 2: Distance-Based Models

KNN uses Euclidean distance: $\sqrt{(x_i - x_j)^2}$

Without scaling:
```
Example: Age=30, Income=$100k vs. Age=32, Income=$500k

Distance = sqrt((30-32)^2 + (100k-500k)^2)
         = sqrt(4 + 400k^2)
         ≈ 400k  ← Income dominates!

Age difference (2 years) is irrelevant; income difference (400k) overpowers.
```

With scaling (both 0-1):
```
Age: 30→0.3, 32→0.32; Income: 100k→0.1, 500k→0.5

Distance = sqrt((0.3-0.32)^2 + (0.1-0.5)^2)
         = sqrt(0.0004 + 0.16)
         ≈ 0.4  ← Both features matter
```

## Scaling Methods

### 1. Standardization (Z-score Normalization)

$$x' = \frac{x - \mu}{\sigma}$$

Where $\mu$ = mean, $\sigma$ = standard deviation.

**Result:** Mean = 0, Std Dev = 1. Values centered around 0, typically in [-3, 3] range.

**Python:**
```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)  # Use train's mean/std
```

**Pros:**
- Works for unbounded ranges (age, temperature)
- Preserves distribution shape
- Default for most algorithms

**Cons:**
- Outliers distort mean/std

### 2. Min-Max Scaling (Normalization)

$$x' = \frac{x - \min(x)}{\max(x) - \min(x)}$$

**Result:** All values in [0, 1].

**Python:**
```python
from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

**Pros:**
- Bounded [0, 1]; interpretable
- Good for neural networks (activation functions work in [0, 1])
- Preserves zero values (if present)

**Cons:**
- Outliers compress data (min/max pulled by extremes)
- If test has value outside train range, scaled value outside [0, 1]

### 3. Robust Scaling

$$x' = \frac{x - \text{median}}{\text{IQR}}$$

Uses median and IQR (robust to outliers).

**Python:**
```python
from sklearn.preprocessing import RobustScaler

scaler = RobustScaler()
X_scaled = scaler.fit_transform(X)
```

**Pros:**
- Robust to outliers (uses IQR, not mean/std/min/max)
- Good when outliers present

**Cons:**
- Less commonly used
- IQR may be small (if data clustered)

### 4. Log Transformation

$$x' = \log(x)$$

For right-skewed data (income, size, duration). Reduces skewness.

**Python:**
```python
X['log_income'] = np.log(X['income'])
X['log_size'] = np.log(X['size'])
```

**Pros:**
- Handles wide ranges elegantly
- Reduces skewness

**Cons:**
- Doesn't work for negative/zero values
- Loses interpretability (log-income hard to explain)
- Must inverse-transform predictions

## When to Scale

| Algorithm | Scale? | Reason |
|-----------|--------|--------|
| Linear Regression | Yes | Gradient descent sensitive to scale |
| Logistic Regression | Yes | Gradient descent |
| SVM | Yes | Distance-based; RBF kernel affected |
| KNN | Yes | Euclidean distance dominated by large scales |
| Neural Networks | Yes | Activation functions work in typical ranges |
| Decision Trees | No | Splits ignore scale |
| Random Forest | No | Each tree splits ignore scale |
| Gradient Boosting | No | Splits ignore scale |

**Rule of thumb:**
- **Gradient-based (linear, logistic, neural nets):** MUST scale
- **Distance-based (KNN, SVM):** MUST scale
- **Tree-based:** No need to scale

## Critical: Prevent Data Leakage

### ✗ WRONG

```python
# Fit scaler on ALL data before splitting
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)  # Fits on all 100 examples

X_train = X_scaled[:70]  # Train
X_test = X_scaled[70:]   # Test
# ← Test statistics (mean, std) influenced scaler training!
```

### ✓ CORRECT

```python
# Split FIRST
X_train = X[:70]
X_test = X[70:]

# Fit scaler on TRAIN only
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)  # Learn mean/std from train

# Apply train's scaler to test
X_test_scaled = scaler.transform(X_test)  # Use train's statistics
```

**Why it matters:**
- Test must be unseen to estimate generalization
- If test statistics influence preprocessing, test isn't truly held-out
- Performance estimate is biased (optimistic)

See [[15.5_Train_Val_Test_Framework]].

## Practical Scaling Workflow

```python
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

# ✓ Correct: Pipeline handles scaling automatically
pipeline = Pipeline([
    ('scaler', StandardScaler()),
    ('model', LogisticRegression())
])

# Train and test (scaler fits on X_train only, applies to X_test)
pipeline.fit(X_train, y_train)
predictions = pipeline.predict(X_test)

# ✓ Or manual (if not using pipeline)
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)

model = LogisticRegression()
model.fit(X_train_scaled, y_train)
predictions = model.predict(X_test_scaled)
```

## Feature Interactions After Scaling

**Scaling doesn't remove multicollinearity** (high correlation between features). It only prevents scale from dominating the problem.

Example: Age and Year-of-Birth are highly correlated. Scaling both doesn't remove correlation; model still gets unstable coefficients. Use regularization (L1/L2) to handle.

---

## Common Pitfalls

| Pitfall | Problem | Fix |
|---------|---------|-----|
| Fit scaler on test data | Test statistics influence preprocessing | Split first, fit scaler on train only |
| Forget to scale for linear model | Gradient descent slow/doesn't converge | Always scale for gradient-based algorithms |
| Use StandardScaler with heavy outliers | Mean/std biased | Use RobustScaler; or remove outliers first |
| Scale tree models | Unnecessary; wastes computation | Don't scale; trees handle raw features |
| Different scalers per feature | Possible but confusing | Use sklearn Pipeline (one consistent scaler) |

## Interview Questions

**Q: Why do you need to scale features for gradient-based algorithms?**

Cost surface becomes elongated (elliptical) without scaling. Gradient descent step size that works for small-scale features (age: 0-100) is too tiny for large-scale features (income: 0-10M). Result: Slow/zigzagging convergence or no convergence. Scaling makes all features 0-1, so cost surface is round (circular); gradient descent converges smoothly and quickly. See [[Common Mistakes in ML#4 - Not Scaling Features]].

---

**Q: What's the difference between StandardScaler and MinMaxScaler?**

**StandardScaler:** $x' = (x - \mu) / \sigma$. Unbounded; works for any range. Outliers distort mean/std. **MinMaxScaler:** $x' = (x - min) / (max - min)$. Bounded [0, 1]; interpretable. Outliers pull min/max, compress data. Use StandardScaler for unbounded data (age, temperature); MinMaxScaler for bounded (probabilities, percentages, neural nets). StandardScaler typical default. See [[15.5_Train_Val_Test_Framework]].

---

**Q: You scale training data with mean=50, std=10. New test example has value=100. After scaling: (100-50)/10=5. Is this OK?**

Yes, fine. Scaled value is 5 (far from typical 0 range), but valid. If test data sometimes exceeds train ranges, scaled values go outside typical [-3, 3] range. Not a problem; model learns to handle extremes. Just ensure you use train's mean/std, not recompute on test. See [[15.5_Train_Val_Test_Framework]].

---

**Q: Do you scale categorical features after one-hot encoding?**

Usually not. One-hot creates binary 0/1 columns; they're already scaled. Scaling would just shift/stretch the 0/1 values (still 0/1, just interpretable differently). For tree models, no scaling needed. For linear models, scaling one-hot is rarely necessary (0/1 range is reasonable). Exception: Scale if you want zero-centered (subtract 0.5 after one-hot). Typically skip this. See [[16.2_Categorical_Encoding]].

---

**Q: If you apply log transformation and then StandardScaler, which is applied first in the pipeline?**

Log transformation first (in preprocessing), then StandardScaler. Log handles skewness (rightskew → normalized shape); StandardScaler then centers and scales the log-transformed distribution. Python sklearn Pipeline applies in order: `Pipeline([('log', LogTransformer()), ('scaler', StandardScaler()), ('model', Model())])`. See [[16.7_Preprocessing_Pipelines]].

## One-line Summary

> Scaling makes gradient-based and distance-based models converge faster and treat all features equally — use StandardScaler (unbounded) or MinMaxScaler (bounded), fit on train only, apply to test, use pipelines to automate — no scaling needed for tree models.
