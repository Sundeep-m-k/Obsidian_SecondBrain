# Categorical Encoding

## What is it?

**Categorical features** have discrete values (categories, classes) rather than continuous numbers:
- Color: Red, Blue, Green
- City: NYC, LA, Chicago
- Education: High School, Bachelor, Master, PhD

Most ML models require numerical input. **Categorical encoding** converts categories into numbers while preserving their meaning.

**Key decision:** Is the categorical feature **ordinal** (ordered: small/medium/large) or **nominal** (unordered: red/blue/green)? Encoding method depends on this.

---

## Ordinal vs. Nominal

### Ordinal: Has Natural Order

**Examples:**
- Education: High School < Bachelor < Master < PhD
- Shirt Size: Small < Medium < Large < XL
- Rating: 1 star < 2 stars < 5 stars

**Meaning:** Higher value > lower value

**Encoding:** Map to integers preserving order
```python
education_map = {'High School': 1, 'Bachelor': 2, 'Master': 3, 'PhD': 4}
df['education_encoded'] = df['education'].map(education_map)
```

**Pros:** Single column; order preserved; works with all models
**Cons:** Model treats gaps as equal (1→2 same distance as 2→3?); can introduce artificial scale

### Nominal: No Inherent Order

**Examples:**
- Color: Red, Blue, Green (no order)
- City: NYC, LA, Chicago
- Country: USA, Canada, Mexico

**Meaning:** Categories are just labels

**Encoding:** Can't use simple integer (assigning 1=Red, 2=Blue, 3=Green implies order!) Use one-hot or other methods.

---

## Encoding Methods

### 1. Label Encoding (Ordinal Only)

**Method:** Map each category to an integer.

```python
# Ordinal: Education
education_map = {'High School': 1, 'Bachelor': 2, 'Master': 3, 'PhD': 4}
df['education'] = df['education'].map(education_map)

# Result: [1, 2, 3, 4, 2, 1, ...] ← Preserves order
```

**Pros:**
- Single column; compact
- Preserves ordinal information
- Works with all models

**Cons:**
- Only for ordinal features
- Numerical model might learn spurious relationships (gap between 1→2 vs. 2→3)
- Tree models may split inefficiently

**When to use:**
- Feature is ordinal (clear order)
- Want compact representation
- Using tree models (robust to scale)

**When NOT to use:**
- Nominal feature (no order)
- Linear models sensitive to scale

---

### 2. One-Hot Encoding

**Method:** Create binary column for each category.

```python
# Nominal: Color
# Original: ['Red', 'Blue', 'Green', 'Red', 'Blue']

# One-hot:
#   Red  Blue  Green
#    1    0      0
#    0    1      0
#    0    0      1
#    1    0      0
#    0    1      0

# sklearn
from sklearn.preprocessing import OneHotEncoder
encoder = OneHotEncoder(sparse_output=False)
encoded = encoder.fit_transform(df[['color']])
```

**Pros:**
- Correct for nominal features (no artificial order)
- Works with all models
- Easy to interpret (each column is a category)

**Cons:**
- Sparse representation (many zeros)
- High dimensionality (k categories → k columns)
- Leads to multicollinearity (sum of columns = 1)

**Dimensionality issue:**
- 10 colors → 10 columns (not too bad)
- 1000 cities → 1000 columns (huge!)
- Must handle categorical features with many unique values

**When to use:**
- Nominal feature
- Few categories (<50)
- Using linear/logistic regression (needs numerical input)

**When NOT to use:**
- Ordinal feature (use label encoding)
- Thousands of categories (use embedding or target encoding)
- Already using tree models (can handle categories directly)

### 3. Ordinal Encoding (Alternative to Label)

**Method:** Similar to label encoding but explicit about order.

```python
from sklearn.preprocessing import OrdinalEncoder

ordinal_encoder = OrdinalEncoder(categories=[['High School', 'Bachelor', 'Master', 'PhD']])
df['education'] = ordinal_encoder.fit_transform(df[['education']])
```

**Pros:**
- Explicit about ordinal intent
- Avoids mistakes (wrong mapping)

**Cons:**
- Same limitations as label encoding
- More verbose than simple mapping

**When to use:**
- Ordinal feature
- Want explicit, sklearn-compatible encoding

---

### 4. Target Encoding (Mean Encoding)

**Method:** Replace category with mean target value for that category.

```python
# Classification: Predict churn (1 or 0)
# City categories: NYC, LA, Chicago

# Churn rate by city:
city_churn_rate = df.groupby('city')['churn'].mean()
# NYC: 0.15, LA: 0.25, Chicago: 0.10

# Encode: Replace city name with its churn rate
df['city_encoded'] = df['city'].map(city_churn_rate)
# 'NYC' → 0.15, 'LA' → 0.25, 'Chicago' → 0.10
```

**Pros:**
- Single column (compact)
- Target information encoded (feature directly predicts target)
- Works well with linear and tree models
- Handles high cardinality (thousands of categories OK)

**Cons:**
- Can overfit (churn rate is noisy for rare categories)
- Category information lost (can't tell which city it is)
- Requires target leakage prevention

**Leakage Prevention:**
```python
# ✓ CORRECT: Fit on train, apply to test
train_city_rate = train_df.groupby('city')['churn'].mean()
X_train['city_encoded'] = X_train['city'].map(train_city_rate)
X_test['city_encoded'] = X_test['city'].map(train_city_rate)

# If city in test but not train, use global mean
X_test['city_encoded'] = X_test['city'].map(lambda x: train_city_rate.get(x, train_df['churn'].mean()))
```

**Handling Rare Categories:**
```python
# Smooth encoding: blend with global mean
smoothing = 1  # Strength of smoothing
global_mean = df['churn'].mean()
category_counts = df.groupby('city').size()

encoded = df.groupby('city')['churn'].transform('mean')
smoothed = (counts * encoded + smoothing * global_mean) / (counts + smoothing)
```

**When to use:**
- Target variable available (supervised)
- Many categories (high cardinality)
- Linear/tree models
- Need compact representation

**When NOT to use:**
- Unsupervised learning (no target)
- Simple baseline (overkill)
- If categories are rare (high variance)

### 5. Embedding / Distributed Representations

**Method:** Learn low-dimensional vectors for each category (used in neural networks).

```python
# Example: Word embeddings (NLP analogy)
# Category: 'NYC' → [0.2, -0.5, 0.1, 0.8] (4-dim embedding)

# Keras Embedding layer
from tensorflow.keras.layers import Embedding
embedding_layer = Embedding(input_dim=num_categories, output_dim=embedding_size)

# Maps each category to learned vector
# Benefit: Captures categorical similarity (related cities close in space)
```

**Pros:**
- Handles high cardinality elegantly
- Learns meaningful relationships
- Compact (<10 dims even for 1000 categories)
- Automatic feature engineering

**Cons:**
- Requires neural network (can't use with linear models)
- Computationally expensive to train
- Less interpretable (vectors are learned, not human-assigned)

**When to use:**
- Deep learning model
- High cardinality (thousands of categories)
- Need to model categorical similarity
- Large dataset

**When NOT to use:**
- Traditional ML (linear, tree models)
- Small data (overfitting risk)
- Need interpretability

## High-Cardinality Categorical Features

**Problem:** Feature with 1000+ unique values (e.g., UserID, ProductID, ZIP code).

**Naive one-hot:** Creates 1000+ columns → sparse, inefficient

### Solutions

#### Solution 1: Target Encoding
```python
# Mean target value per category
user_conversion_rate = df.groupby('user_id')['purchased'].mean()
df['user_id_encoded'] = df['user_id'].map(user_conversion_rate)
# 1000 → 1 column
```

#### Solution 2: Frequency Encoding
```python
# Replace with how often category appears
user_freq = df['user_id'].value_counts()
df['user_id_freq'] = df['user_id'].map(user_freq)
# NYC: 50,000 → 'NYC' encoded as 50,000
```

#### Solution 3: Hash Encoding
```python
# Hash category to fixed number of buckets
from sklearn.feature_extraction import FeatureHasher
hasher = FeatureHasher(n_features=10, input_type='string')
hashed = hasher.transform(df[['user_id']])
# Maps 1000 categories → 10 dimensions
```

#### Solution 4: Grouping Rare Categories
```python
# Combine rare categories into "Other"
value_counts = df['category'].value_counts()
rare_threshold = 100
df['category'] = df['category'].apply(
    lambda x: x if value_counts[x] >= rare_threshold else 'Other'
)
```

## Workflow: Choosing Encoding

```
Categorical feature detected
        ↓
Is it ordinal (has order)?
        ├─ Yes → Label encode (map to integers preserving order)
        │
        └─ No (nominal)
           ├─ How many categories?
           │
           ├─ Few (<50)
           │  └─ One-hot encoding
           │
           └─ Many (50-1000+)
              ├─ Supervised (target available)?
              │  └─ Target encoding (mean target per category)
              │
              └─ Unsupervised
                 └─ Embedding (DL) or frequency encoding
```

## Common Pitfalls

| Pitfall | Problem | Fix |
|---------|---------|-----|
| One-hot encode ordinal | Loses order information; artificial dimensionality | Use label encoding for ordinal |
| Label encode nominal | Creates artificial order ("Red"=1 < "Blue"=2) | Use one-hot for nominal |
| Target encoding without leakage prevention | Test statistics influence train encoding | Fit encoder on train, apply to test |
| One-hot for high-cardinality | Sparse, inefficient (1000 columns) | Use target encoding or embedding |
| Forget categories in new data | Model crashes when unseen category appears | Handle with smoothing or "Other" |
| Treat category as string in model | Most models crash; require numerical input | Always encode before training |

## Interview Questions

**Q: What's the difference between label encoding and one-hot encoding? When would you use each?**

**Label encoding:** Map categories to integers (e.g., Small=1, Medium=2, Large=3). Use for **ordinal features** (order matters). **One-hot encoding:** Create binary column per category (Small=[1,0,0], Medium=[0,1,0], Large=[0,0,1]). Use for **nominal features** (no order). Using label on nominal creates artificial order (Red=1 < Blue=2 implies Blue is "greater"); incorrect. Using one-hot on ordinal wastes columns (3 dimensions vs 1). See [[Common Mistakes in ML#4]].

---

**Q: You have a categorical feature with 5000 unique values (e.g., product IDs). How would you encode it?**

One-hot would create 5000 columns (sparse, inefficient). Instead: (1) **Target encoding:** Replace with mean target value per product. Single column, captures predictive signal. (2) **Frequency encoding:** Replace with how often product appears. (3) **Embedding (DL):** Learn 10-50 dimensional vector per product. (4) **Grouping:** Combine rare products as "Other"; reduces to maybe 100 categories. For supervised learning, target encoding is typical. See [[16.3_Outlier_Detection]].

---

**Q: What is target encoding and why is it powerful for high-cardinality features?**

Target encoding replaces category with its mean target value. Example: If NYC has 15% churn and LA has 25% churn, replace city names with 0.15 and 0.25. Powerful because: (1) Single column (compact). (2) Directly encodes predictive signal (correlates with target). (3) Handles any cardinality (1000 categories OK). (4) Works with all models. Risks: Overfits on rare categories (small sample size → noisy mean). Mitigate with smoothing: blend category mean with global mean. Must fit on train only, apply to test (prevent leakage). See [[15.5_Train_Val_Test_Framework]].

---

**Q: If you use target encoding, how do you handle unseen categories in the test set?**

Categories appearing in test but not train. Options: (1) **Use global mean:** Replace unseen categories with overall target mean. (2) **Use default value:** Special encoding for "unseen." (3) **Smoothing:** Already blend with global mean during training; reduces overfitting. Example: During training, use smoothed encoding `(count * category_mean + smoothing * global_mean) / (count + smoothing)`. For unseen, use `global_mean`. This handles both rare and unseen categories gracefully. See [[16.6_Data_Leakage_Prevention]].

---

**Q: When would you use embeddings instead of one-hot or target encoding for categorical features?**

Embeddings (learned vectors) are useful in deep learning when: (1) High cardinality (1000+ categories). (2) Categorical similarity matters (related products should be close in embedding space). (3) Have large dataset (enough to train embeddings). Example: In recommendation systems, user/product embeddings capture preferences. One-hot doesn't scale; target encoding loses category identity. Embeddings learn rich, low-dimensional representations. Downside: Only works with neural networks; slow to train. For traditional ML (linear, trees), use target encoding. See [[15.4_Cross_Validation_Strategy]].

---

**Q: What does one-hot encoding do to multicollinearity?**

Creates it. One-hot on k categories makes k binary columns that sum to 1 (perfect multicollinearity). Example: Color with Red=[1,0,0], Blue=[0,1,0], Green=[0,0,1]. Sum of columns always equals 1. For linear regression, this causes (X^TX) to be singular (non-invertible); sklearn fixes it by dropping one column (the reference). For tree models, no problem (trees don't care about multicollinearity). For neural networks, mild problem (adds training difficulty). Standard practice: Drop one column (or use regularization). sklearn OneHotEncoder handles this with drop='first'. See [[16.7_Preprocessing_Pipelines]].

## One-line Summary

> Ordinal features use label encoding (preserves order); nominal features use one-hot (few categories) or target encoding (high cardinality) — always prevent leakage by fitting encoder on train and applying to test, and handle unseen categories via smoothing or global mean.
