# Multiple Testing Correction

## What is it?

**Multiple testing problem:** Running many statistical tests increases false positive rate. If you run 100 tests with α=0.05, expect ~5 false positives even if all nulls are true.

**Correction:** Adjust p-value threshold to account for multiple tests. Trade-off: Fewer false positives, more false negatives (lower power).

---

## The Problem

### Inflation of Type I Error Rate

**Single test:** α = 0.05 (5% false positive rate)

**100 independent tests:** False positive rate = $1 - (1 - 0.05)^{100} \approx 0.994 = 99.4%$

Almost certainly get ≥1 false positive!

### Example: Feature Selection

```
Dataset: 1000 features, target is random noise

Run 1000 t-tests (one per feature vs. target)
With α=0.05, expect ~50 features to be "significant"
Even though none truly matter (target is random)

Researcher picks the 50 significant features and builds model
← Model overfits; does poorly in validation
```

---

## Correction Methods

### 1. Bonferroni Correction

**Method:** Divide significance level by number of tests.

$$\alpha_{\text{adjusted}} = \frac{\alpha}{m}$$

Where $m$ = number of tests.

**Example:** 100 tests, α=0.05
$$\alpha_{\text{adjusted}} = \frac{0.05}{100} = 0.0005$$

Only reject if p < 0.0005 (much stricter).

**Equivalently:** Multiply each p-value by $m$, reject if adjusted p < α.

```python
from scipy.stats import ttest_ind
import numpy as np

# 100 features, target
p_values = []
for i in range(100):
    p_val = ttest_ind(X[:, i], y)[1]
    p_values.append(p_val)

# Bonferroni correction
m = len(p_values)
adjusted_p_values = np.array(p_values) * m
adjusted_p_values = np.clip(adjusted_p_values, 0, 1)  # Cap at 1

# Reject if adjusted_p < 0.05
significant = adjusted_p_values < 0.05
```

**Pros:**
- Simple
- Strongly controls false positives
- Exact; no assumptions

**Cons:**
- Very conservative (high false negatives)
- Loses power with many tests
- Assumes tests are independent (fails with correlated features)

**When to use:** Few tests (< 10); want to be very safe

### 2. Benjamini-Hochberg FDR Control

**Method:** Order p-values, find threshold that controls false discovery rate (FDR).

**FDR:** Expected proportion of false discoveries among all discoveries.

**Example:** FDR=0.05 means ~5% of discoveries are false positives.

**Procedure:**
1. Sort p-values: $p_{(1)} \leq p_{(2)} \leq \cdots \leq p_{(m)}$
2. For each $i$, compute threshold: $p_{(i)} \leq \frac{i}{m} \alpha$
3. Find largest $i$ satisfying this; reject hypotheses 1 through $i$

```python
from scipy.stats import rankdata
import numpy as np

# P-values
p_values = np.array([0.001, 0.008, 0.039, 0.041, 0.042, ...])

# Sort
sorted_indices = np.argsort(p_values)
sorted_p = p_values[sorted_indices]
m = len(p_values)

# Find threshold
alpha = 0.05
for i in range(m - 1, -1, -1):
    if sorted_p[i] <= (i + 1) / m * alpha:
        threshold_index = i
        break
else:
    threshold_index = -1

# Reject hypotheses up to threshold
if threshold_index >= 0:
    rejected = sorted_indices[:threshold_index + 1]
    print(f"Reject {len(rejected)} hypotheses")
else:
    print("Reject 0 hypotheses")
```

**Pros:**
- Less conservative than Bonferroni (higher power)
- Works for dependent tests (correlated features)
- Practical; balances false positives and negatives

**Cons:**
- FDR ≠ individual error rate (different interpretation)
- Less strict than Bonferroni

**When to use:** Many tests (> 10); want to balance discoveries and false positives

### 3. Holm-Bonferroni (Intermediate)

**Method:** Progressive Bonferroni. Start with strict correction, relax for remaining tests.

1. Sort p-values
2. Test smallest p-value with $\alpha / m$
3. If significant, test 2nd smallest with $\alpha / (m-1)$
4. Continue until non-significant

**Pros:**
- Less conservative than Bonferroni
- Simpler than Benjamini-Hochberg

**Cons:**
- More complicated logic
- Less power than FDR

**When to use:** Middle ground between Bonferroni and FDR

## When to Correct

### Correct When:

1. **Running multiple statistical tests on same data**
   - 100 feature t-tests
   - Multiple model comparisons

2. **Exploring data without pre-specified hypotheses (exploratory)**
   - Data mining
   - Feature selection

### Don't Need to Correct When:

1. **Tests are pre-specified** (before looking at data)
   - Registered hypothesis
   - One primary comparison planned

2. **Tests answer different questions** (not testing multiple hypotheses on same phenomenon)
   - Model A accuracy
   - Model A latency
   - (Different metrics; not multiple comparisons)

3. **Using cross-validation properly**
   - CV already controls false positives (multiple folds validate stability)
   - Don't correct CV fold p-values

## Correction and Cross-Validation

**CV + Hypothesis Testing:**

```python
from sklearn.model_selection import cross_val_score
from scipy import stats

# 5-fold CV
cv_scores_model_a = cross_val_score(ModelA, X, y, cv=5)
cv_scores_model_b = cross_val_score(ModelB, X, y, cv=5)

# T-test on CV scores
t_stat, p_value = stats.ttest_rel(cv_scores_model_a, cv_scores_model_b)

# NO correction needed
# CV itself controls for overfitting
# Single t-test answers single question
print(f"p-value: {p_value:.3f}")
if p_value < 0.05:
    print("Models significantly different")
```

**When CV scores WOULD need correction:**

```python
# Run 100 different models, compare each to baseline
# 100 t-tests → need correction
p_values = []
for model in models:
    scores_model = cross_val_score(model, X, y, cv=5)
    scores_baseline = cross_val_score(baseline, X, y, cv=5)
    _, p_val = ttest_rel(scores_model, scores_baseline)
    p_values.append(p_val)

# Apply Benjamini-Hochberg to p_values
# (This corrects for 100 comparisons)
```

## Common Pitfalls

| Pitfall | Problem | Fix |
|---------|---------|-----|
| No correction for multiple tests | False positive rate inflates; many spurious discoveries | Apply Bonferroni or FDR |
| Bonferroni when many tests | Too strict; lose power | Use Benjamini-Hochberg for balance |
| Correct CV fold p-values | Unnecessary; CV already controls | Don't correct CV comparisons |
| P-hacking (run tests until p<0.05) | Almost guaranteed false positive | Pre-register hypothesis; correct for multiple |

## Interview Questions

**Q: What is the multiple testing problem and how do you fix it?**

Running $m$ independent tests with α=0.05 gives false positive rate ≈ $1 - (0.95)^m$. Example: 100 tests → ~99.4% chance ≥1 false positive. Solution: Adjust p-value threshold. **Bonferroni:** $\alpha_{\text{adj}} = \alpha / m$; strict, loses power. **Benjamini-Hochberg:** Controls FDR (false discovery rate); less conservative, works for dependent tests. Use Bonferroni for few tests; FDR for many. Caveat: Doesn't apply to cross-validation (CV controls false positives already). See [[17.2_Hypothesis_Testing_and_P_Values]].

---

**Q: You run 10 feature selection t-tests and 2 have p < 0.05. Should you include those features?**

Not without correction. With 10 tests, expect ~0.5 false positives even if all features are noise (10 × 0.05 = 0.5). Your 2 significant features might be false positives. Apply correction: Bonferroni: $p < 0.05 / 10 = 0.005$ (much stricter). Benjamini-Hochberg: More lenient. Correct for multiple testing, then decide. Or, use cross-validation to validate selected features (prevents false positives naturally). See [[15.4_Cross_Validation_Strategy]].

---

**Q: Do you need to correct p-values when doing 5-fold cross-validation?**

No. Each fold is held-out test; validation prevents false positives. The 5 fold accuracies directly estimate generalization. If comparing two models via CV, single t-test on fold scores (no correction needed) answers: "Are models significantly different?" One question = one test. Only correct when running multiple independent tests on same data (e.g., 100 feature tests). CV inherently controls overfitting. See [[15.4_Cross_Validation_Strategy]].

---

**Q: What's the difference between Bonferroni and Benjamini-Hochberg correction?**

**Bonferroni:** Divide α by number of tests. $p < \alpha / m$ to reject. Conservative; controls family-wise error rate (probability ≥1 false positive among all tests). Loses power with many tests. **Benjamini-Hochberg:** Order p-values, find threshold that controls FDR (expected % false among discoveries). Less strict; more power. Doesn't assume independence. Use Bonferroni for few critical tests (want 100% safety). Use FDR for exploratory analysis (balance discoveries vs. false positives). See [[17.2_Hypothesis_Testing_and_P_Values]].

## One-line Summary

> Multiple testing inflates false positives (100 tests with α=0.05 gives ~99% false positive rate); correct with Bonferroni (strict, few tests) or Benjamini-Hochberg FDR (lenient, many tests) — CV doesn't need correction as it inherently controls overfitting.
