# Online vs. Offline Evaluation

## What is it?

**Offline evaluation:** Test on historical data (logged predictions + outcomes).
**Online evaluation:** A/B test in production (new model vs. baseline).

Offline = development; Online = deployment validation.

---

## Offline Evaluation

### Process

1. Train model on historical data
2. Evaluate on held-out test set (or validation set)
3. Metrics: Accuracy, precision, recall, AUC
4. Decision: Meet threshold? Ship or iterate

### Pros

- Fast (no real users involved)
- Cheap (data already collected)
- Reproducible (same data = same results)
- Safe (no production impact)

### Cons

- Test set may not reflect production distribution (data drift)
- Can't measure real-world effects (engagement, revenue)
- Optimization myopia (optimize for test metric, wrong metric)

---

## Online Evaluation (A/B Testing)

### Process

1. Train model
2. Deploy alongside baseline (A/B test in production)
3. Route ~50% users to new model, ~50% to baseline
4. Measure real business metrics (clicks, revenue, retention)
5. Analyze statistical significance
6. Decide: Roll out or rollback

### Example

```python
# Day 1-7: A/B test
# Group A (50%): Old model
# Group B (50%): New model

# Metrics
new_model_ctr = 0.035  # Click-through rate
old_model_ctr = 0.033

# Statistical test
from scipy.stats import chi2_contingency
table = [[new_clicks, new_impressions - new_clicks],
         [old_clicks, old_impressions - old_clicks]]
chi2, p_value, _, _ = chi2_contingency(table)

if p_value < 0.05:
    print("New model significantly better. Rollout.")
else:
    print("No significant difference. Keep baseline.")
```

### Pros

- Measure real business impact
- Detect unintended consequences (increased latency, user confusion)
- Statistical validation (p-values, confidence intervals)
- Real-world performance

### Cons

- Slower (wait for statistical significance)
- Expensive (divert real users to potentially worse model)
- Need large sample size for significance
- Can't test all ideas (too slow, too many interactions)

---

## Hybrid Approach

**Phase 1: Offline evaluation**
- Test on historical data
- Achieve baseline performance

**Phase 2: Shadow testing**
- Deploy new model in "shadow" (no real traffic)
- Compare predictions, latency, errors vs. baseline
- Cheap confidence check

**Phase 3: Canary deployment**
- Deploy to 5% of users
- Monitor for bugs, latency, errors
- If good, gradually increase (10%, 25%, 100%)

**Phase 4: A/B test (if needed)**
- Test on 50% of users
- Measure business metrics
- Decide to rollout or rollback

## Statistical Considerations

### Sample Size Needed

For power = 0.8, α = 0.05, minimum detectable effect size = 1%:

Sample size ∝ 1 / (effect_size)²

- Detect 5% difference: ~1000 samples
- Detect 1% difference: ~25,000 samples

Larger effect sizes need fewer samples.

### Multiple Comparisons

Testing many metrics inflates false positives. Apply correction (Benjamini-Hochberg) or pre-specify primary metric.

See [[17.3_Multiple_Testing_Correction]].

## Interview Questions

**Q: Why would you A/B test a model that performs well offline?**

Offline metrics may not reflect real business goals (optimized for accuracy, but users care about relevance). A/B test measures actual impact on engagement, retention, revenue. Example: Model A gets 92% accuracy offline but confuses users (lower engagement). Model B gets 88% accuracy but users prefer it. A/B test reveals this. Also detects unintended consequences (slower inference, more errors in edge cases). Offline ≠ online always. See [[18.1_Data_Drift_and_Concept_Drift]].

---

**Q: You need to decide between two models. Offline: Model A=92%, Model B=91%. Online (7-day A/B test): A CTR=3.2%, B CTR=3.3%, p=0.08. Decision?**

Offline: Model A wins. Online: Statistically inconclusive (p > 0.05). Don't have enough data. Options: (1) Run longer (wait for significance). (2) Accept smaller effect (0.1% lift might be too small anyway). (3) Choose on other criteria (latency, cost, interpretability). Don't rollout Model B without statistical confidence. See [[17.2_Hypothesis_Testing_and_P_Values]].
