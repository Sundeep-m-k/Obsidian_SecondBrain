# Retraining and Model Maintenance

## What is it?

**Retraining:** Rebuilding model on new data to adapt to distribution/concept drift.

**Maintenance:** Ongoing activities to keep model healthy (monitoring, retraining, updates).

---

## Retraining Triggers

### 1. Performance Degradation

Monitor accuracy/precision/recall; retrain if drops.

```python
if accuracy_today < 0.90:  # Threshold
    trigger_retraining()
```

### 2. Scheduled Retraining

Retrain weekly/monthly regardless of performance.

**Rationale:** Drift is gradual; may not trigger threshold until too late.

```python
if day_of_week == "Sunday":
    trigger_retraining()
```

### 3. Data Volume

Retrain when collect enough new labeled data.

```python
new_labeled_data_count = count_recent_labels()
if new_labeled_data_count > 10000:
    trigger_retraining()
```

### 4. Manual (Ad Hoc)

Retrain if:
- Business rules change
- Data distribution known to shift (seasonality)
- Fraud patterns change

---

## Retraining Strategies

### Cold Start

Retrain from scratch on recent data.

```python
# Collect last 30 days of data
recent_data = get_labeled_data(days=30)
model = train_model(recent_data)
validate(model)  # Test on hold-out
deploy(model)
```

**Pros:** Fresh model, no old patterns
**Cons:** Slow (long training); can lose good old patterns

### Warm Start

Fine-tune existing model on new data.

```python
model = load_model("production_model_v2.3")
model.fit(recent_data, epochs=5)  # Few epochs
validate(model)
deploy(model)
```

**Pros:** Fast (transfer learning)
**Cons:** May overfit to recent data; forget old patterns

### Incremental Learning

Update model continuously as new data arrives.

```python
for x, y in stream_of_new_data():
    model.partial_fit([x], [y])  # Online learning
```

**Pros:** Always up-to-date
**Cons:** Complex infrastructure; harder to debug

## Retraining Workflow

```
Monitor performance daily
        ↓
Detect drift / performance drop
        ↓
Collect recent labeled data
        ↓
Retrain model (cold start or warm start)
        ↓
Validate on hold-out recent test set
        ↓
If performance good: Deploy (canary, then full)
        ↓
If performance poor:
  - Investigate root cause
  - Feature engineering?
  - Data quality?
  - Model architecture?
```

## Interview Questions

**Q: Your model's accuracy drops from 92% to 85% in one week. What do you do?**

(1) Investigate: Is it data drift or concept drift? Check input distribution (KS test). (2) Collect recent labeled data (last 7-30 days). (3) Try retraining on recent data. (4) Validate on hold-out recent test set. (5) If performance recovers → deploy retrained model. (6) If not → deeper investigation (feature drift, labeling errors, business change). Set alert thresholds to catch this earlier (e.g., 90% vs. 85% threshold). See [[18.1_Data_Drift_and_Concept_Drift]].

---

## One-line Summary

> Retrain when performance drops, on schedule, or when drift detected; use cold start (from scratch) or warm start (fine-tune) depending on data volume and time; validate before deployment; monitor continuously.
