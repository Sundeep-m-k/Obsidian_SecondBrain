# Data Drift and Concept Drift

## What is it?

**Data drift:** Distribution of input features changes over time. Model trained on old data, sees new data with different distribution.

**Concept drift:** Relationship between features and target changes. P(y|x) changes over time.

Both cause model performance degradation in production.

---

## Data Drift (Covariate Shift)

### Definition

Input feature distribution $P(X)$ changes, but $P(Y|X)$ stays same.

**Example:** Model trained on summer user demographics; deployed in winter. Age/location/device distribution shifted.

**Impact:** Model sees unfamiliar feature patterns; predictions unreliable.

### Detection Methods

#### 1. Kolmogorov-Smirnov (KS) Test

Compare distributions: Training vs. Production

```python
from scipy.stats import ks_2samp

# Training distribution
X_train_feature = [...training feature values...]

# Production batch
X_prod_feature = [...production feature values...]

# KS test
ks_stat, p_value = ks_2samp(X_train_feature, X_prod_feature)

if p_value < 0.05:
    print("Significant drift detected")
```

**Pros:** Intuitive; detects differences in univariate distributions
**Cons:** Ignores multivariate relationships

#### 2. Wasserstein Distance

Measure how much to "move" one distribution to match another.

```python
from scipy.stats import wasserstein_distance

distance = wasserstein_distance(X_train, X_prod)
```

**Pros:** Intuitive metric
**Cons:** Univariate only

## Concept Drift

### Definition

Relationship $P(Y|X)$ changes. Even if features stay same, target distribution changes.

**Example:** Fraud detection model. Fraudsters change tactics over time; old patterns no longer work.

### Detection via Model Performance

Monitor model accuracy/precision/recall over time. If drops, likely concept drift.

```python
# Day 1: Model accuracy 92%
# Day 7: Model accuracy 85%
# Day 30: Model accuracy 78% ← Concept drift
```

### Root Causes

1. **Temporal patterns:** Market cycles, seasonality
2. **Adversarial:** Fraudsters adapting to bypass model
3. **External events:** COVID-19, regulatory changes
4. **Natural shift:** User behavior evolution

---

## Combined: Data + Concept Drift

Most real-world scenarios have both:

```
Data Drift: Feature distribution P(X) shifts
         ↓
Concept Drift: Target relationship P(Y|X) shifts
         ↓
Model Performance: Drops (sometimes catastrophically)
```

## Handling Drift

### 1. Detection and Alerting

Monitor distributions; trigger alert if drift threshold exceeded.

```python
def detect_drift(X_train, X_current, threshold=0.05):
    for feature in X_train.columns:
        ks_stat, p_value = ks_2samp(X_train[feature], X_current[feature])
        if p_value < threshold:
            return True, feature
    return False, None

drift_detected, drifted_feature = detect_drift(X_train, X_prod_batch)
if drift_detected:
    alert(f"Drift in {drifted_feature}")
```

### 2. Retraining

Retrain model on recent data (with drift) to adapt.

```python
# Collect recent production data
recent_data = get_last_30_days_labeled_data()

# Retrain model
model.fit(recent_data['X'], recent_data['y'])

# Evaluate on recent test set
accuracy = evaluate(model, test_data)

# If good, deploy; if poor, investigate
```

### 3. Online Learning

Update model incrementally with new data.

```python
# Instead of retraining from scratch
for x, y in stream_of_new_data():
    model.partial_fit([x], [y])  # SGDClassifier, online models
```

**Pros:** Continuous adaptation
**Cons:** Complex; requires streaming infrastructure

### 4. Passive Monitoring

Don't actively detect drift; just monitor performance. Alert if performance drops.

**Pros:** Simple
**Cons:** Slow; miss drift until performance suffers

---

## Monitoring Strategy

```
Step 1: Log predictions + ground truth
Step 2: Compute daily accuracy
Step 3: Alert if accuracy drops > threshold
Step 4: Investigate root cause (data drift vs. concept drift)
Step 5: Retrain if drift confirmed
Step 6: Validate on held-out recent data
Step 7: Deploy if performance acceptable
```

## Interview Questions

**Q: What's the difference between data drift and concept drift?**

**Data drift:** Input distribution P(X) changes; relationship P(Y|X) stays same. Example: Summer users (age 20-40) → Winter users (age 30-50). Model still works if trained on features it understands. **Concept drift:** Relationship P(Y|X) changes; inputs might stay same. Example: Fraud patterns change (fraudsters adapt). Model accuracy drops even if features look normal. Both degrade performance; need monitoring to detect. See [[18.2_Model_Monitoring_in_Production]].

---

**Q: How would you detect data drift in production?**

Compare training vs. production distributions using statistical tests. Options: (1) **KS test:** Univariate drift detection; simple, interpretable. (2) **Wasserstein distance:** Probability-based distance. (3) **MMD:** Multivariate; complex. (4) **Performance monitoring:** Indirect; watch accuracy drop. Python: `ks_2samp(X_train_feature, X_prod_feature)`. If p < 0.05, drift detected. Monthly or weekly checks sufficient for most systems. See [[18.2_Model_Monitoring_in_Production]].

---

**Q: You detect concept drift. What do you do?**

(1) Investigate root cause (fraud changing, seasonality, external event). (2) Collect recent labeled data (last 30-90 days). (3) Retrain model on recent data. (4) Validate on held-out recent test set. (5) If performance good, deploy retrained model. (6) If poor, may need feature engineering or new approach. Prevention: Build online learning pipeline so model adapts continuously (harder to implement but reduces manual retraining). See [[18.6_Retraining_and_Model_Maintenance]].
