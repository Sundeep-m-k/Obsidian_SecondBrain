# Class Imbalance Evaluation

## What is it?

**Class imbalance** occurs when one class dominates the data (e.g., 99% negative, 1% positive). Standard metrics like accuracy become misleading. Evaluation must account for the asymmetry.

**Key insight:** With 99% negative class, a model predicting "always negative" gets 99% accuracy but catches 0% of positives. Metrics must reveal this weakness.

---

## Why Standard Metrics Fail

### Accuracy Illusion

```
Data: 1000 examples, 990 negative (99%), 10 positive (1%)

Model A: Always predicts negative
- Accuracy = 990/1000 = 99% ✓ (looks good!)
- Recall = 0/10 = 0% ✗ (catches nothing)
- Precision = undefined (predicts 0 positives)

Model B: Smart classifier
- Accuracy = 950/1000 = 95% ✗ (looks worse!)
- Recall = 8/10 = 80% ✓ (catches most)
- Precision = 8/50 = 16% ✗ (many false alarms)
```

Model A looks better by accuracy but is useless. Model B is actually useful.

### The Problem

Accuracy = $\frac{TP + TN}{n}$. With 99% negatives, TN dominates. Even terrible classification on positives looks acceptable.

**Solution:** Use metrics insensitive to class imbalance.

---

## Metrics for Imbalanced Data

### 1. Precision and Recall

$$\text{Precision} = \frac{TP}{TP+FP}, \quad \text{Recall} = \frac{TP}{TP+FN}$$

**Key property:** Don't depend on TN (which dominates in imbalanced data).

**Example:** Model predicting [+, +, -, -, -] on true [+, -, +, -, -]:
- TP = 1, FP = 1, FN = 1, TN = 2
- Precision = 1/2 = 0.5 (only 50% of predicted positives are correct)
- Recall = 1/2 = 0.5 (only 50% of actual positives caught)
- Accuracy = (1+2)/5 = 0.6 (but misleading with imbalance)

### 2. F1 Score

$$F_1 = 2 \cdot \frac{P \cdot R}{P + R}$$

Harmonic mean of precision and recall. Single metric for imbalanced data.

**Property:** Penalizes extreme imbalance between P and R.

### 3. AUC-PR (Area Under Precision-Recall Curve)

Plots Precision vs. Recall across all thresholds; integrates to get AUC-PR.

**Why better than AUC-ROC for imbalance:** Focuses on positive class. Baseline is $\approx \frac{\text{# positives}}{n}$ (e.g., 0.01 for 1% positive), not 0.5. Any improvement above baseline is visible.

See [[15.2_ROC_and_PR_Curves]] for details.

### 4. Matthews Correlation Coefficient (MCC)

$$\text{MCC} = \frac{TP \cdot TN - FP \cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}$$

Ranges from -1 to +1. Balanced metric independent of class ratio.

**Interpretation:**
- MCC = +1: Perfect
- MCC = 0: Random
- MCC = -1: Worst (perfectly wrong)

**Advantage:** Single number; doesn't hide weakness like F1 can.

## Weighted Metrics

### Macro vs. Micro Averaging

For multi-class imbalance, define metrics differently:

#### Macro: Average per-class metrics

$$\text{Macro F}_1 = \frac{1}{K} \sum_{k=1}^K F_{1,k}$$

Each class weighted equally. Use when all classes matter equally.

#### Micro: Aggregate then compute

$$\text{Micro F}_1 = \frac{2 \sum_k TP_k}{\text{denominators}}$$

Larger classes weighted more. Use when class frequency reflects importance.

### Weighted: Scaled by Class Frequency

$$\text{Weighted F}_1 = \sum_{k=1}^K \frac{n_k}{n} F_{1,k}$$

Weight each class's metric by its proportion in data. Use when class frequency matters.

## Cost-Sensitive Learning

In imbalanced problems, FP and FN often have different costs.

**Example:** Cancer screening
- FN (miss cancer): Patient doesn't get treatment; severe cost
- FP (false alarm): Unnecessary follow-up; mild cost
- Ratio: $c_{FN}/c_{FP} \approx 100/1$

### Handling via Class Weights

Most models allow class weights. Internally, model scales loss by class:

$$J = \frac{1}{n} \sum_i w_{y_i} \ell_i$$

Where $w_0$ = weight for negatives, $w_1$ = weight for positives.

**sklearn syntax:**
```python
from sklearn.linear_model import LogisticRegression
model = LogisticRegression(class_weight='balanced')
# Automatically sets w_k = n / (K * n_k)
# For 1% positive: w_1 = 100, w_0 = 1.01
```

### Handling via Threshold Tuning

Increase threshold to predict "positive" more conservatively → increases precision, lowers recall. Use when FP cost is high.

Decrease threshold to predict "positive" more liberally → increases recall, lowers precision. Use when FN cost is high.

See [[Thresholding]] for detailed guidance.

## Sampling Strategies

### Oversampling Minority Class

Duplicate minority examples to balance data.

**Pros:**
- Simple
- No information loss
- Works with any model

**Cons:**
- Duplication can cause overfitting
- Large datasets become huge

### Undersampling Majority Class

Remove majority examples.

**Pros:**
- Reduces training time

**Cons:**
- Throws away data (information loss)
- Can undersample important majority examples

### SMOTE (Synthetic Minority Over-sampling Technique)

Generate synthetic minority examples by interpolating between neighboring minority examples.

**Pros:**
- No information loss
- No duplication
- Synthetics are plausible

**Cons:**
- More complex
- Can generate out-of-distribution examples

**Example:** Minority example $x_i$, nearest minority neighbor $x_j$:
$$x_{\text{synthetic}} = x_i + \lambda (x_j - x_i), \quad \lambda \sim U(0,1)$$

## Evaluation Workflow for Imbalanced Data

```
1. Choose appropriate metric:
   - Multiclass: Macro F1 (all classes matter)
   - Binary imbalance: Precision, Recall, F1
   - Severe imbalance (>100:1): AUC-PR
   - Cost asymmetry known: Cost-weighted metric

2. Use stratified CV:
   - Preserve class distribution in each fold
   - Prevents fold with 95% majority by accident

3. Avoid accuracy:
   - Never report as primary metric
   - Always report precision/recall together

4. Try multiple approaches:
   - Class weights
   - Threshold tuning
   - Oversampling/undersampling
   - SMOTE

5. Evaluate on test set:
   - Report all metrics: Precision, Recall, F1, AUC-PR
   - Include confusion matrix
   - Show what% of minority class caught (recall)
```

## Common Pitfalls

| Pitfall | Problem | Fix |
|---------|---------|-----|
| Report accuracy only | Misleading on imbalanced data | Report Precision, Recall, F1, AUC-PR |
| Random split (not stratified) | Folds have different class ratios | Use StratifiedKFold |
| Default threshold (0.5) | Suboptimal for asymmetric costs | Tune via ROC or PR curve |
| Oversampling before split | Synthetic duplicates leak into test | Oversample only in train |
| Ignore cost of FP vs. FN | Optimize for wrong metric | Align threshold with business cost |

## Interview Questions

**Q: Why is accuracy a bad metric for imbalanced data? What should you use instead?**

With 99% negative class, a model always predicting "negative" gets 99% accuracy but catches 0% of positives. Accuracy is dominated by TN (true negatives on the majority class) and hides poor performance on minority class. Use Precision (of predicted +, how many correct), Recall (of actual +, how many caught), F1 (harmonic mean), or AUC-PR (area under precision-recall curve). These don't depend on TN. See [[15.1_Classification_Metrics]].

---

**Q: What are class weights and how do they help with imbalance?**

Class weights scale the loss per example by its class. With 1% positive minority, set $w_1 = 100, w_0 = 1$. During training, a positive example's error is weighted 100×, forcing the model to prioritize minority class. sklearn's class_weight='balanced' automatically computes $w_k = n / (K \cdot n_k)$. Effect: Model trades off some majority-class accuracy for minority-class recall. See [[16.5_Class_Imbalance_Handling]].

---

**Q: When would you use oversampling, undersampling, or SMOTE for imbalanced data?**

**Oversampling:** Simple; duplicates minority examples. Risk: Exact duplicates cause overfitting. Use for small data.
**Undersampling:** Removes majority examples. Risk: Throws away data. Use when data is huge and can afford to discard.
**SMOTE:** Generates synthetic minority examples by interpolation. Best practice; no duplication, no information loss. Use for general imbalanced problems.

All three should be applied within CV folds (after train/val split) to avoid leakage. See [[16.5_Class_Imbalance_Handling]].

---

**Q: Should you oversample before or after train/val split?**

**After split** (correct): Oversample only in train fold. Synthetic data doesn't leak into val/test. Results are honest.

**Before split** (wrong): Oversample all data, then split. Synthetic minority examples end up in val/test. Model is over-optimistic; real performance lower.

Sklearn SMOTE should be used inside CV pipeline or applied to train set only. See [[15.4_Cross_Validation_Strategy]].

---

**Q: Given Precision=0.9, Recall=0.5, what does this tell you about an imbalanced classifier?**

High precision, low recall: Model is conservative (predicts positive rarely). When it predicts positive, it's usually right (90%). But it misses many actual positives (only catches 50%). Suggests threshold is too high. Lower it to increase recall (catch more positives) at cost of precision (more false alarms). F1 = 2·(0.9·0.5)/(0.9+0.5) = 0.643 (mediocre; recall is bottleneck). For imbalance, low recall is often worse than low precision (missing positives costlier). See [[15.1_Classification_Metrics]].

---

**Q: How do you select a threshold for imbalanced data?**

From precision-recall curve: Maximize F1 if both FP and FN costs similar. Or set threshold to minimize $c_{FP} \cdot FP + c_{FN} \cdot FN$. Example: Cancer screening where FN cost is 100× FP cost; choose lower threshold (predict positive more often, catch more cancer at cost of false alarms). Tune on validation set, evaluate on test set. See [[Thresholding]].
